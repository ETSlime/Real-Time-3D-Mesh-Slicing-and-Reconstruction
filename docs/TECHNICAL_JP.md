# Mesh Cut：技術解説

[プロジェクト概要](../README_JP.md) · [中文](TECHNICAL_CN.md) · **日本語** · [English](TECHNICAL_EN.md)

## 1. 概要と機能範囲

Mesh Cut は、C++、DirectX 11、DirectXMath を用いたインタラクティブなメッシュ切断デモです。ウィンドウ上のマウスドラッグから切断平面を作成し、CPU上で三角形を裁断し、閉形状は輪郭復元と封口、開いた表面は封口なしで処理して描画用モデルを再構築します。

平面切断、交点属性の補間、閉形状の凹輪郭封口と独立した非入れ子輪郭、開いた表面の封口なし切断、生成後の再切断に対応します。OBJ のドラッグ＆ドロップでモデルを切り替え、F1 で塗りつぶし／ワイヤーフレーム、F3 で切断平面の表示を切り替えられます。2つの履歴スタックによる取り消し／やり直しに対応し、操作ガイドはDebug／Releaseの両方で表示します。

ここでの切断は、三角形表面の再生成と両側の位置分離を意味します。コリジョン生成や剛体シミュレーションは含みません。

## 2. モジュールとデータフロー

| モジュール | 役割 |
|---|---|
| `main.cpp` | ドロップ要求、表示モードのキー入力、更新と描画の実行 |
| `ObjImporter` | OBJ／MTL の解析と頂点・インデックス・サブセット・材質データの生成 |
| `player.cpp` | 切断操作、平面変換、アルゴリズム呼び出し、結果の一時保持とモデル更新 |
| `MeshCutter` | 数学補助、補間、クリッピング、交線、輪郭三角形分割、封口 |
| `ModelSnapshot.h / .cpp` | 独立したモデル状態の保存、テクスチャ参照の保持、CPU／GPUリソースの復元 |
| `ModelHistory.h / .cpp` | 2つの履歴スタック、切断履歴の確定、取り消し／やり直しと消去 |
| `renderer.cpp` | DirectX リソースと、塗りつぶし・カリングの組み合わせ管理 |
| `camera.cpp` | 透視カメラ、行列更新、初期状態への復帰 |

`MeshCutter.h` は型とインターフェース、`.cpp` は非テンプレート定義、`.inl` はテンプレート定義を保持します。`.inl` はヘッダー末尾からインクルードします。切断自体は CPU データで計算しますが、現在のクラスには DirectXMath の座標変換補助も含まれ、公開ヘッダーが DirectX 非依存というわけではありません。

処理順序は以下のとおりです。

1. マウス操作からワールド空間の切断平面を生成。
2. 平面をモデルのローカル空間へ変換。
3. サブセットの三角形を展開し、永続破片番号で入力を整理。
4. 破片内で材質をまたいで表面を切り分け、共通交点と断面線分を収集。
5. 交点を統合。閉形状は閉輪郭を復元して二次元へ投影。
6. 閉形状は入れ子検査と耳切り封口。開いた表面は封口を省略。
7. 封口属性を設定し、切れた破片だけを分離。最終接続を確認して新番号を生成。
8. 全サブセットを一時保持し、切断前の状態を保存。CPU／GPUリソースの準備後にモデルと履歴を確定。

## 3. マウス操作と切断平面

### 3.1 スクリーン座標からレイ方向を求める

ウィンドウ座標 $(s_x,s_y)$ を正規化デバイス座標へ変換します。

$$
x_{ndc}=\frac{2s_x}{w}-1,\qquad y_{ndc}=1-\frac{2s_y}{h}
$$

$w,h$ は現在の `SCREEN_WIDTH / SCREEN_HEIGHT` です。Y は、ウィンドウ座標と投影座標の上下方向が異なるため反転します。

対称な透視投影では、垂直視野角 $\theta_y$、アスペクト比 $a$ に対して：

$$
P_{11}=\frac{1}{\tan(\theta_y/2)},\qquad P_{00}=\frac{P_{11}}{a}
$$

ビュー空間の $z=1$ 上で対応する方向を求めます。

$$
D_{view}=\left(\frac{x_{ndc}}{P_{00}},\frac{y_{ndc}}{P_{11}},1\right)
$$

`CreateWorldRayDirection()` はこの方向を逆ビュー行列でワールド空間へ変換し、正規化します。方向に平行移動は適用しません。レイ原点は、ビュー空間の原点を逆ビュー行列で変換して取得します。

添字は0始まりで、$P_{00}$ と $P_{11}$ は投影行列のX／Y方向の拡大率です。両方が1なら、垂直視野角 $90^\circ$、アスペクト比1の対称透視投影に相当し、正射影ではありません。方向は `w=0` で作成し、`XMVector3TransformNormal()` で変換するため、カメラの平行移動を含みません。

$P_{00}/P_{11}$ による除算を省いても正射影にはなりません。同じ原点から広がるレイのまま、実際のカメラと投影条件が一致しなくなります。現在の式は通常の対称透視投影と全画面ビューポートを前提とし、正射影や非対称投影用の処理ではありません。

### 3.2 2本のレイから平面を生成する

開始・終了レイの単位方向を $D_s,D_e$、共通原点を $O$ とすると：

$$
N=\mathrm{normalize}(D_e\times D_s),\qquad Q=O
$$

切断平面は次を満たします。

$$
(P-Q)\cdot N=0
$$

2ピクセル未満のドラッグは無視します。また、外積の長さの二乗が $10^{-12}$ 未満の場合も、安定した法線を作れないため処理を中止します。

### 3.3 ドラッグ範囲による受け入れ条件

数学的な平面は無限に広がるため、断面線分の両端を `IsInsideStroke()` で検査します。交点をワールド・ビュー・投影行列で変換し、一度だけ透視除算してスクリーン座標へ戻し、開始・終了点が作る軸平行矩形と比較します。各方向に2ピクセルの余白を設けています。

これは点とドラッグ線分との厳密な距離判定ではありません。現在は $w\leq10^{-5}$ の交点も除外します。有効な断面線分の端点が条件を満たさなければ、その破片は `Unchanged` となります。他の破片は独立して切断できます。判定は材質ごとではなく破片全体の切り口に適用します。

`SliceModel()` はこの判定をコールバックとして受け取ります。画面上の制約が不要な呼び出しでは、常にtrueを返すコールバックを渡せます。

## 4. 切断平面のローカル空間への変換

描画と切断で同じワールド行列を使用します。行ベクトル規約における順序は：

$$
W=SRT
$$

現在のモデル姿勢には、Y 軸に $\pi$ を加える向き補正が含まれます。平面上の点と法線は異なる行列で変換します。

$$
Q_{local}=Q_{world}W^{-1}
$$

$$
N_{local}=\mathrm{normalize}(N_{world}W^T)
$$

一般に法線は「使用する座標変換行列の逆転置」で変換します。今回は座標変換が $W^{-1}$ なので：

$$
\left((W^{-1})^{-1}\right)^T=W^T
$$

となり、非一様スケールでも対応する平面への垂直性を維持します。ワールド行列が可逆であることを前提とし、ゼロスケールを有効な操作として扱いません。

## 5. 三角形入力、破片、符号付き距離

`CutMeshes()` は `IndexArray` から展開三角形を取得し、全材質サブセットを `SliceModel()` へ渡します。サブセットは描画材質の区分であり、閉じた物体の単位ではありません。1つの破片が複数サブセットにまたがる場合があります。

初回は `InitializePieceIds()` が材質をまたぐ幾何接続から破片番号を作ります。以後は全体を位置で再接続せず、各三角形の永続的な破片番号でまとめます。分離後に異なる破片が重なっても同一視せず、中央の破片だけを切る場合は他の位置・属性・番号を維持します。

各破片内で共通位置番号を作り、単位切断平面法線に対して：

$$
d=(P-Q)\cdot N
$$

正値が正側、負値が負側です。これは切断平面の法線であり、表面の照明用法線ではないため、全サブセットが同じ平面を共有します。既定の位置許容誤差はローカル単位で $\epsilon=10^{-4}$ です。距離は共通位置ごとにdoubleで計算し、$|d|\leq\epsilon$ なら分類をゼロにして出力用の共通位置を平面へ投影します。入力配列は変更しません。

厳密な両側に頂点を持たない破片は切断しません。許容誤差はモデルスケールに依存し、任意のアセットで同じ精度を保証する値ではありません。

### 5.1 開いた表面と閉形状の分類

`ClassifyInputSurface()` は共通位置番号と既存の辺接続を利用します。各試行の有効許容誤差で、独立成分内の材質をまたいで無向辺を集計します。全辺が2面共有なら閉形状として共有辺の向きも確認し、1面だけの境界辺があれば開いた表面とします。3面以上の共有や潰れた辺は境界として許可せず、拒否します。

`SliceComponentAttempt()` は両者でクリッピングと操作範囲判定を共有します。閉形状は閉輪郭復元と封口へ進み、開いた表面は閉輪郭・穴検査・封口を省いて分離した表面だけを返します。有効な切口線分と両側の非空出力は必要です。混在時も成分ごとに処理して一括確定し、どれかが失敗した場合は更新全体を中止します。封口失敗から開放処理への切り替えは行いません。

`AssignSidePieceIds()`／`AssignNewPieceIds()` は既存検証へ `requireClosed` を渡し、閉形状だけに出力の閉合を要求します。永続フィールドやスナップショット形式の追加は不要です。独立形状番号は開いた連結表面も表し、必ずしも体積を持ちません。

境界だけでは意図的な薄板と面が欠けた殻を区別できず、両方を開いた表面として扱います。元の面方向を保持し、頂点順や法線は自動修復しません。

## 6. 半空間クリッピングと頂点属性

### 6.1 両側の半空間を生成する

`ClipSubset()` が材質グループの三角形を処理し、`AppendClippedTriangle()` が両側を個別に出力します。残す条件は：

$$
d\times side\geq0
$$

`side=+1` は正側、`side=-1` は負側で、平面上の頂点は両側の境界に含みます。元の境界順で辺 A→B を処理します。両端が平面上にない通常のケースでは：

| Aが残す範囲内 | Bが残す範囲内 | 追加する頂点 |
|---|---|---|
| はい | はい | A |
| はい | いいえ | A、交点 |
| いいえ | はい | 交点 |
| いいえ | いいえ | なし |

平面上の元頂点は、その辺の始点として追加します。辺内部の新交点は距離が厳密に異符号の場合だけ生成し、元端点の重複補間を避けます。両側は計算済みの交点を再利用します。

結果は境界順を保つ凸多角形なので、三角ファン $(P_0,P_i,P_{i+1})$ で分割できます。通常の横断では単独頂点側が三角形、反対側が四角形となり、後者を2三角形へ分割します。横断されない面は所属側へ入ります。このファンは元表面の裁断用であり、凹形状になり得る断面には後段の耳切り法を使います。

### 6.2 補間と共通位置

辺の両端の距離が $d_A,d_B$ なら、辺上の距離は $d(t)=d_A+t(d_B-d_A)$ です。これをゼロとすると：

$$
t=\frac{d_A}{d_A-d_B},\qquad P=A+t(B-A)
$$

同じ係数で位置、UV、RGBA頂点色、法線を線形補間し、法線は再正規化します。係数が0または1なら対応する元頂点を直接返し、補間丸めで端点位置が変わることを防ぎます。

`InterpolateSharedEdge()` は端点順を統一してdoubleで位置を計算し、共通辺番号でキャッシュします。元表面と切断面は同じ代表位置を使用しますが、法線・UV・色は各三角形の描画頂点から補間するため、材質境界や属性の継ぎ目を位置と一緒に統合しません。未対応の追加フィールドは端点Aを引き継ぎ、接線やボーン属性の自動対応は意味しません。

### 6.3 三角形の登録

`Triangle()` は指定順を維持し、doubleで外積を求め、実際に面積ゼロの面を除外します。位置許容誤差の二乗より小さいという理由だけで有効な面を個別に消すと隙間が生じるため、その方法は使用しません。非ゼロ面積だけでは十分でなく、最終的な接続も確認します。

## 7. 断面線分と共通トポロジー

元表面の三角形と封口輪郭は別の出力ですが、交点計算を共有します。`ClipSubset()` の三角形単位の `hits` は切断ノード番号であり、封口三角形や閉輪郭全体ではありません。`AppendUniqueIndex()` がノード番号の重複を除きます。

| 段階 | 識別方法と役割 |
|---|---|
| 共通元頂点 | 共通位置番号により隣接面の分類を一致させる |
| 辺内部の交点 | 無向の端点番号対で交点位置をキャッシュする |
| 切断ノード | 許容誤差内の代表位置を元表面と封口で共有する |
| 断面線分 | 無向ノード対ごとに隣接面の正負側情報を集める |

### 7.1 切り口と同側接触の区別

三角形内部を横切る線分は、直接両側の情報を持ちます。既存辺を通る場合、1つの三角形は片側情報しか持たないため、破片内の全材質グループを処理した後で辺の情報を統合します。正側・負側の両方がある辺だけを輪郭隣接表へ入れます。両隣接面が同じ側なら接触であり、切り口ではありません。頂点だけの接触による孤立ノードに閉輪郭は要求しません。

既存辺に沿う切断は成功し得ますが、外表面への接触は `Unchanged` となり得ます。実際の分割中に三角形全体が共面となる場合や接続が一意に決まらない退化状態は、引き続き更新を拒否する場合があります。一時出力は検証後にのみ採用します。

## 8. 隣接関係と閉じた輪郭

`nodes[i]` が交点、`adjacency[i]` が接続先番号です。線分 AB を A→B、B→A の両方向に記録します。

以下の閉輪郭条件は閉形状の封口に適用し、開いた表面には要求しません。`BuildClosedContours()` は有効線分に属さない隣接数ゼロの接触ノードを除き、参加ノードの隣接数が2であることを確認し、未訪問ノードから、直前ではない方の隣接ノードへ進みます。

- 開始点へ戻る：閉じた輪郭が完成。
- 開始点以外の訪問済みノードへ入る：失敗。
- 隣接数が2以外、または輪郭が3ノード未満：失敗。
- 未訪問ノードが残る：別の独立輪郭として処理。

各ステップで未訪問ノードを登録し、開始点または訪問済みノードで終了するため、有効なノード番号の下では無限巡回しません。隣接数2の確認は接続構造の検査であり、幾何学的自己交差の完全な検査ではありません。

## 9. 平面座標への投影と入れ子検査

投影・方向判定の中間値にはdoubleを使用します。単位法線とほぼ平行にならない参考軸 R を選びます。現在は $|N_x|<0.9$ で X 軸、それ以外で Y 軸を使用します。

$$
U=\mathrm{normalize}(R\times N),\qquad V=N\times U
$$

$U\times V=N$ となる基底で、交点を投影します。

$$
p_u=(P-Q)\cdot U,\qquad p_v=(P-Q)\cdot V
$$

`projected[i]` は `nodes[i]` と同じノードを表し、`loops` は順序付きノード番号を保持します。

`IsPointInsideContour()` は右向き水平レイと境界の交差回数の奇偶で内外を判定します。`HasNestedContours()` は各輪郭の代表ノードが別の輪郭の内部にあるか調べます。

輪郭が単純で、互いに交差・接触しないことを前提とする代表点判定です。完全な輪郭交差検査ではありません。入れ子を検出したら `UnsupportedHole` を返し、穴を塗りつぶした面で塞ぎません。

## 10. 頂点順と耳切り法

### 10.1 反時計回りへ統一

符号付き面積の2倍は：

$$
A_2=\sum_i(x_i y_{i+1}-y_i x_{i+1})
$$

負なら輪郭を反転します。実装では先頭点を相対原点にして累積し、大きな座標での桁落ちを抑えます。

### 10.2 耳の選択

隣り合う A、B、C に対して：

$$
\mathrm{Orient}(A,B,C)=(B_x-A_x)(C_y-A_y)-(B_y-A_y)(C_x-A_x)
$$

反時計回りでは正値が凸角です。候補は十分に確かな正方向を持ち、他の輪郭頂点を含まない必要があります。そうでなければ境界を越えたり別の領域を覆ったりする可能性があります。有効な耳の中では最小高さが大きい三角形を優先し、細長い面を減らします。ABCを保存し、作業輪郭からBだけを削除して続けます。

方向と三角形内判定はdoubleと行列式の演算量に応じた誤差限界を使用し、位置許容誤差の二乗を一律の方向閾値にしません。作業用はコピーで、元ノードは保持します。n点の単純境界で成功するとn−2三角形を生成します。耳が見つからない、または分割を完了できない場合は `TriangulationFailed` です。

`TriangulateContours()` はノード番号の三つ組 `TriangleIndices` を出力し、封口頂点生成と分離しています。

### 10.3 境界の保持と数値安定性

ほぼ共線の境界を一時的に簡略化しても、省いたノードを三角形分割へ戻し、元表面と切断面の境界分割を一致させます。境界を変えない範囲で内部辺を有限回改善し、短辺を削除して接続エラーを隠すことはしません。

分離後のfloat座標で封口の向きを確認し、必要なら実際の移動後座標で再分割します。既存平面は、元の向き、近共面性、共通法線、近似的にアフィンなUV、一様な頂点色が許す場合だけ再構築し、意味のある属性の継ぎ目を保護します。

`OpenOrAmbiguousContour` または `TriangulationFailed` の場合、同じ入力と平面のまま、破片内の位置許容誤差を最大2回半減して再試行できます。float座標間隔と距離計算誤差による下限を設けます。切断平面は移動せず、`Unchanged`、不正入力、穴では再試行しません。

## 11. 両側の切断面、法線、UV

閉形状に対してのみ、`AppendCapTriangles()` がノード番号から両側の切断面を生成します。`CreateCapVertex()` は位置や頂点色を引き継ぎ、法線とUVを上書きします。

| 側 | 切断面の外向き法線 | 頂点順 |
|---|---|---|
| 負側 $d\leq0$ | $+N$ | A、B、C |
| 正側 $d\geq0$ | $-N$ | C、B、A |

頂点順は幾何学的な向き、`Normal` は照明用属性を表すため、両方を設定します。元表面と切断面の境界は同じ位置でも別の法線を持ち、ハードエッジを表現します。

平面UVは：

$$
(UV_x,UV_y)=(p_u,p_v)\times uvScale
$$

既定の `uvScale=0.1` を使用し、断面全体を自動的に [0,1] へ正規化しません。範囲外の見え方はサンプラーと材質に依存します。封口は独立出力し、アプリが既存材質を選択します。専用材質は作らず、材質をまたぐ封口を元材質境界で再分割する必要もありません。

実際に切れた破片の元表面と切断面を一緒に移動し、未切断破片は動かしません。

$$
P_-=P-N\times separation,\qquad P_+=P+N\times separation
$$

既定値は各側1.5ローカル単位で、元々重なっていた切断面間は3単位離れます。完了時に `Status::Cut` を返し、生成された頂点が次の切断入力になります。

## 12. 破片結果、材質保持、モデル更新

`SliceModel()` は永続破片内で材質をまたいだ輪郭を復元します。`ModelResult::subsets` は元材質ごとの切断表面、`caps` は封口、`unchangedSubsets` は未切断破片を保持し、三角形ごとの破片番号も扱います。閉形状は材質単独で閉輪郭を作る必要はありません。開いた表面の `caps` は空で、表面と番号は同じ結果インターフェースで返します。

- `Cut`：新表面と閉形状に必要な封口を採用し、切れた成分だけを分離。
- 破片の `Unchanged`：元の形状・属性・番号を保ち、分離しない。
- 他の失敗が1つでも発生：部分成功を提出せず、モデル更新全体を中止。
- 全体が未変更：リソース再構築も履歴追加も行わない。

最終分離座標で閉形状は各辺の2面共有を要求します。開いた表面では1面だけの境界を許可しますが、3面以上の共有は拒否します。新しい番号も形状と一時保持し、置換成功時にのみモデルへ設定します。

`CutMeshes()` は元表面と材質の対応を維持します。封口は既存材質を使用し、専用材質は作りません。容量確認後、`TryUpdateModel()` が展開頂点・連番インデックス・サブセット／材質・独立GPUバッファを準備し、全成功後に旧モデルを解放します。現在の16ビット形式では最大65,535展開頂点です。

| ステータス | 意味 |
|---|---|
| `Unchanged` | 元の破片またはモデルを維持 |
| `Cut` | 新表面・必要な封口・独立形状番号の準備完了 |
| `InvalidInput` | 入力形式、番号、設定が条件を満たさない |
| `OpenOrAmbiguousContour` | 閉形状の輪郭が開放、または分岐・共面の曖昧さ・不正な接続。開いた表面すべての拒否ではない |
| `UnsupportedHole` | 未対応の入れ子輪郭 |
| `TriangulationFailed` | 輪郭分割または必要な安全な再分割が完了しない |

これらはアルゴリズム結果であり、頂点容量超過やGPU作成失敗はアプリ側の提出段階の拒否です。失敗では一時形状を取り付けず、成功切断の履歴も増やしません。

## 13. 所有権と失敗時の処理

| リソース | 管理方法 |
|---|---|
| 提出前のサブセット配列 | `unique_ptr<SimpleArray<VERTEX_3D>>` |
| 更新キューへ渡した一時配列 | `QueueCleanup` が終了時に削除・キューをクリア |
| 提出前のCPU配列 | `unique_ptr<T[]>` |
| 提出前のGPUバッファ | `BufferOwner` が失敗終了時に `Release()` |
| 提出済みモデル | `UnloadModel()` がテクスチャ参照、バッファ、配列、外側の `MODEL` を解放 |

材質キューのテクスチャポインターは借用で、キュー破棄時には `Release()` しません。新サブセットごとに旧モデル解放前に `AddRef()` し、旧サブセットの参照を解放しても共有テクスチャが有効な状態を維持します。

CPU配列の提出には `release()`、GPUバッファには提出後の所有者ポインターのクリアを使用します。局所的なクリーンアップ型は、実際にオブジェクトを生成して初めてデストラクターによる処理が働きます。

既存のアルゴリズムエラー、引数・容量拒否、メモリ確保失敗、バッファ作成失敗を扱います。任意の入力破損やすべての例外を回復する仕組みではありません。`SimpleArray` 内部の解放はコンテナーの既存デストラクター規約に依存します。

## 14. スナップショットと取り消し／やり直し

### 14.1 保存する状態

`ModelSnapshot` は頂点、インデックス、サブセットと材質の独立した配列を保存します。位置、法線、頂点色、UVに加え、以前の切断で生成された切断面や分離移動もモデル状態に含まれます。三角形ごとの `TrianglePieceIds` と `NextPieceId` も保存し、取り消し／やり直しで破片の識別を復元します。GPUバッファ、カメラ、表示用モデル変換、塗りつぶし設定、切断平面の表示設定は保存しません。

`Capture()` はCPU配列をディープコピーしますが、テクスチャ画素は複製しません。保存するサブセットごとにテクスチャへ `AddRef()` し、スナップショットの破棄時に対応する `Release()` を行います。コピーは禁止し、`unique_ptr<ModelSnapshot>` で所有します。

`Restore()` は保存したインデックスとサブセット範囲を維持してCPU配列を作成し、頂点／インデックスバッファを再作成します。切断用の一時キューを経由せず、幾何アルゴリズムも再実行しません。準備完了後、復元モデル用のテクスチャ参照を取得し、`UnloadModel()` で旧モデルを解放して置換します。メモリ確保やバッファ作成に失敗した場合、現在のモデルを維持します。

### 14.2 2つのスタック

`ModelHistory` は、取り消し用とやり直し用の2つの `std::stack<std::unique_ptr<ModelSnapshot>>` を使用します。現在表示中のモデルそのものをスタック先頭に置くのではなく、復元先となる他の状態を保存します。

| 操作 | 復元元 | 現在の状態の保存先 |
|---|---|---|
| 元に戻す | 取り消しスタックの先頭 | やり直しスタック |
| やり直す | やり直しスタックの先頭 | 取り消しスタック |

Aから2回の切断でCになった場合、現在はC、取り消しスタックは底からA、Bです。1回戻すと現在はB、取り消し側はA、やり直し側はCになります。さらに戻すと現在はA、やり直し側は底からC、Bとなり、やり直しではB、Cの順に復元します。

同じスナップショットをスタック間で移動する処理ではありません。Bを復元する際、反対側へ保存するのは直前に取得した現在状態Cです。

### 14.3 モデル更新と履歴の確定

切断アルゴリズムと容量確認の後、`PrepareCut()` で旧モデルを保存して取り消しスタックへ一時追加し、`TryUpdateModel()` でモデルを更新します。局所オブジェクト `CutHistoryGuard` が終了時に `FinishCut()` を呼びます。

更新成功時は記録を確定してやり直し履歴を破棄します。失敗時は一時記録だけを取り消し、やり直し履歴を維持します。未切断、アルゴリズム拒否、容量超過では履歴を追加しません。スナップショットを保存できなければ、切断結果も提出しません。

取り消し／やり直しでも、現在状態の取得と反対側への追加をモデル変更前に行います。追加時にメモリ確保が発生する可能性があるためです。復元失敗時は追加した記録を削除して復元元を残し、成功した場合だけ復元元を取り除きます。履歴なしは `S_FALSE`、復元成功は `S_OK` で、どちらもHRESULTの失敗ではありません。

別モデルの読み込み成功時は両履歴を消去し、読み込み失敗時は維持します。取り消し後に新しい切断が成功すると編集が分岐し、以前のやり直し履歴は破棄されます。終了時も明示的に履歴をクリアし、スナップショットとテクスチャ参照を解放します。

### 14.4 入力とリソース範囲

`Ctrl+Z` で元に戻し、`Ctrl+Y` または `Ctrl+Shift+Z` でやり直します。左右のCtrl／Shiftに対応し、Z／Yの押下開始を検出するため、押し続けても毎フレーム実行しません。切断線のドラッグ中は履歴操作を受け付けません。復元成功時は古い切断平面プレビューを無効化し、表示スイッチ、塗りつぶし設定、カメラは維持します。

履歴はメモリ上のみで、ファイルに保存しません。差分ではなくCPU形状全体を保存し、現在は件数やメモリ量の上限を設定していません。長時間編集では履歴に応じてメモリ使用量が増加します。テクスチャはCOM参照で共有し、画素や各履歴のGPUメッシュバッファを複製・保持し続けません。

## 15. OBJドロップとリセット

`DragAcceptFiles()` と `WM_DROPFILES` で単一OBJのパスを受け取り、メッセージ処理では要求だけを保存します。実際の同期読み込みは次の更新処理で行います。

ワイド文字パスはローダーが使う Windows ANSI コードページへ変換し、表現できない文字を拒否します。区切り文字を `/` に統一して関連ファイルを解決します。完全なUnicode対応ではなく、MTL／テクスチャの参照名は空白を避け、既存パーサーの形式に合わせることを推奨します。

`ReplacePlayerModel()` は一時モデルへ読み込み、成功した場合だけCPUデータと2つのGPUバッファを交換し、旧リソースを解放します。失敗時は表示中のモデルと履歴を維持します。成功時は取り消し／やり直し履歴を消去します。

成功後は位置・回転・拡大率、移動慣性、ドラッグ状態、切断平面データ、カメラを初期状態へ戻します。同じOBJを再ドロップすると未切断形状へ戻せます。Rは表示状態だけを戻し、形状を再読み込みしません。ドロップ操作を切断と誤認しないよう、ドラッグを取り消して左ボタンの解放を待ちます。

読み込みは同期処理で、バックグラウンドスレッドは使用しません。モデルの自動センタリングやサイズに応じたカメラ調整も行いません。

## 16. 表示モードと操作ガイド

F1で `D3D11_FILL_SOLID / D3D11_FILL_WIREFRAME` を切り替えます。塗りつぶし2種類とカリング3種類の計6状態を事前作成し、両方の選択を記録して適用するため、`SetCullingMode()` がワイヤーフレーム設定を上書きしません。

F3で切断平面を表示／非表示にします。頂点バッファへの書き込み成功も必要で、最初の有効なドラッグ前は未初期化の平面を描きません。プレビューは2本のレイ上の距離15と300の点から作る四角形で、この距離は数学的切断範囲を制限しません。

プレビューは最後に作成を試みた平面を表し、切断が拒否された場合も更新されることがあります。モデルのリセットや取り消し／やり直しの成功時に古い平面を無効化し、表示設定は維持します。現在の塗りつぶし設定はプレビューにも適用されます。

`PrintDebugProc()` で毎フレーム操作ガイドを登録し、`DrawDebugProc()` から `DebugTextOut()` を呼び出して描画します。F1／F3の状態と履歴ショートカットはDebug／Releaseの両方で表示します。`DEBUG_DISP_TEXTOUT` を有効にした構成でBGRAバックバッファとGDI互換スワップチェーンを使用し、D3DデバッグレイヤーはDebugでのみ有効にします。カメラ操作とRリセットもDebug／Releaseの両方で有効です。

| 入力 | 操作 |
|---|---|
| 左ドラッグ後に解放 | 切断を試行 |
| 単一OBJのドロップ | モデル置換とリセット。成功時に履歴を消去 |
| Ctrl + Z | 元に戻す |
| Ctrl + Y / Ctrl + Shift + Z | やり直す |
| F1 | 塗りつぶし／ワイヤーフレーム |
| F3 | 切断平面の表示／非表示 |
| 矢印キー | カメラ方向を基準にモデルを移動 |
| A / D | カメラの水平旋回 |
| W / N | カメラの上昇／下降 |
| U / M | カメラの接近／後退 |
| R | モデル姿勢とカメラをリセット。形状は維持 |
| Esc | 終了 |

カメラ旋回はA／D、上昇はWを使用し、Z／Yを使用しません。カメラ側でCtrlとの競合を判定する必要はありません。

## 17. 実行環境、コスト、制限

WindowsのVisual StudioプロジェクトでC++17を使用し、DirectX 11、DirectXMath、入力、D3DX11の依存関係を設定します。Shader／アセットの相対パスと作業ディレクトリーを一致させ、法線・UV・有効なMTL／テクスチャ参照を持つ三角形化済みOBJを使用します。

| 項目 | 現在の範囲 |
|---|---|
| 入力形状 | 閉形状と開いた表面に対応。閉形状は共有辺の向きを確認し、開いた表面は入力方向を維持。境界判定は薄板と欠損殻を区別せず、修復・厚み追加・全自己交差の検出保証は行わない |
| 断面 | 単純な凹輪郭と独立した非入れ子輪郭。穴、曲線の刃、任意の立体ブーリアンは未対応 |
| 退化とスケール | 接触は未変更、実際の分割中の全面共面や曖昧な接続は拒否となり得る。float保存と有限誤差では任意スケール・極細形状・無限回の切断を保証せず、許容誤差内の投影／統合で微細部を失う場合がある |
| 属性 | 許容誤差を超えるUVの継ぎ目、非アフィンUV、非一様色を壊す必要がある修復は拒否し得る。一般の多材質やUVの継ぎ目を非対応とする意味ではない |
| 破片識別 | 識別済み破片は番号で独立維持。初回は幾何接続を推定するため重合入力の独立識別は保証せず、衝突や重なりのブーリアン結合は行わない |
| 容量と履歴 | アプリ内で最大65,535展開頂点。完全CPUスナップショットは履歴とともに増え、予算制限や永続化はない。頂点上限はD3D11一般の上限ではない |

クリッピングは三角形を走査し、共通辺／線分はマップで管理しますが、位置照合には線形探索も残ります。n点輪郭の耳候補検査は最悪 $O(n^3)$ となり得ます。境界復元、品質改善、有限再試行の追加処理もあり、全体を線形とは主張しません。一時メモリは入出力形状、接続マップ、輪郭に応じて増えます。置換時は新旧リソースが共存し、履歴はCPU形状と番号を別途保存してテクスチャ参照を共有します。

検証は多材質、凹断面、既存辺／頂点、部分切断、重なり、連続切断を含みます。平面・開いたキャラクター・開放／閉鎖混在では面積・属性・番号を確認し、閉形状は閉合・頂点順・体積誤差も検査します。これらの成功は全入力での成功保証ではありません。

推奨デモ：立方体 → 材質をまたぐ封口 → L字プリズムの凹断面 → 中央破片だけの切断 → 取り消し／やり直しと分岐 → F1／F3で確認 → OBJ再ドロップ。
