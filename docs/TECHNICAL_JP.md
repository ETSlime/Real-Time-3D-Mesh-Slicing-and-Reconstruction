# Mesh Cut：技術解説

[プロジェクト概要](../README_JP.md) · [中文](TECHNICAL_CN.md) · **日本語** · [English](TECHNICAL_EN.md)

## 1. 概要と機能範囲

Mesh Cut は、C++、DirectX 11、DirectXMath を用いたインタラクティブなメッシュ切断デモです。ウィンドウ上のマウスドラッグから切断平面を作成し、CPU 上で三角形のクリッピング、断面輪郭の復元、両側の切断面生成を行い、描画用モデルを再構築します。

平面切断、交点属性の補間、単純な凹輪郭の封口、複数の独立した非入れ子輪郭、生成後のメッシュに対する再切断に対応します。OBJ のドラッグ＆ドロップでモデルを切り替え、F1 で塗りつぶし／ワイヤーフレーム、F3 で切断平面の表示を切り替えられます。2つの履歴スタックによる取り消し／やり直しに対応し、操作ガイドはDebug／Releaseの両方で表示します。

ここでの切断は、三角形表面の再生成と両側の位置分離を意味します。コリジョン生成や剛体シミュレーションは含みません。

## 2. モジュールとデータフロー

| モジュール | 役割 |
|---|---|
| `main.cpp` | ドロップ要求、表示モードのキー入力、更新と描画の実行 |
| `ObjImporter` | OBJ／MTL の解析と頂点・インデックス・サブセット・材質データの生成 |
| `player.cpp` | 切断操作、平面変換、アルゴリズム呼び出し、結果の一時保持とモデル更新 |
| `MeshCutter` | 数学補助、補間、クリッピング、交線、輪郭三角形分割、封口 |
| `ModelSnapshot.h / .cpp` | 独立したモデル状態の保存、テクスチャ参照の保持、CPU／GPUリソースの復元 |
| `ModelHistory.h / .cpp` | 2つの履歴スタック、切断履歴の確定、取り消し／やり直しと消去 |
| `renderer.cpp` | DirectX リソースと、塗りつぶし・カリングの組み合わせ管理 |
| `camera.cpp` | 透視カメラ、行列更新、初期状態への復帰 |

`MeshCutter.h` は型とインターフェース、`.cpp` は非テンプレート定義、`.inl` はテンプレート定義を保持します。`.inl` はヘッダー末尾からインクルードします。切断自体は CPU データで計算しますが、現在のクラスには DirectXMath の座標変換補助も含まれ、公開ヘッダーが DirectX 非依存というわけではありません。

処理順序は以下のとおりです。

1. マウス操作からワールド空間の切断平面を生成。
2. 平面をモデルのローカル空間へ変換。
3. インデックスを解決して、サブセット単位の展開三角形を取得。
4. 元の表面を切り分け、断面の交線を収集。
5. 交点を統合し、閉じた輪郭を復元して二次元へ投影。
6. 入れ子輪郭を検査し、耳切り法で封口用三角形を生成。
7. 両側の封口属性を設定し、全頂点をそれぞれの側へ移動。
8. 全サブセットを一時保持し、切断前の状態を保存。CPU／GPUリソースの準備後にモデルと履歴を確定。

## 3. マウス操作と切断平面

### 3.1 スクリーン座標からレイ方向を求める

ウィンドウ座標 $(s_x,s_y)$ を正規化デバイス座標へ変換します。

$$
x_{ndc}=\frac{2s_x}{w}-1,\qquad y_{ndc}=1-\frac{2s_y}{h}
$$

$w,h$ は現在の `SCREEN_WIDTH / SCREEN_HEIGHT` です。Y は、ウィンドウ座標と投影座標の上下方向が異なるため反転します。

対称な透視投影では、垂直視野角 $\theta_y$、アスペクト比 $a$ に対して：

$$
P_{11}=\frac{1}{\tan(\theta_y/2)},\qquad P_{00}=\frac{P_{11}}{a}
$$

ビュー空間の $z=1$ 上で対応する方向を求めます。

$$
D_{view}=\left(\frac{x_{ndc}}{P_{00}},\frac{y_{ndc}}{P_{11}},1\right)
$$

`CreateWorldRayDirection()` はこの方向を逆ビュー行列でワールド空間へ変換し、正規化します。方向に平行移動は適用しません。レイ原点は、ビュー空間の原点を逆ビュー行列で変換して取得します。

添字は0始まりで、$P_{00}$ と $P_{11}$ は投影行列のX／Y方向の拡大率です。両方が1なら、垂直視野角 $90^\circ$、アスペクト比1の対称透視投影に相当し、正射影ではありません。方向は `w=0` で作成し、`XMVector3TransformNormal()` で変換するため、カメラの平行移動を含みません。

$P_{00}/P_{11}$ による除算を省いても正射影にはなりません。同じ原点から広がるレイのまま、実際のカメラと投影条件が一致しなくなります。現在の式は通常の対称透視投影と全画面ビューポートを前提とし、正射影や非対称投影用の処理ではありません。

### 3.2 2本のレイから平面を生成する

開始・終了レイの単位方向を $D_s,D_e$、共通原点を $O$ とすると：

$$
N=\mathrm{normalize}(D_e\times D_s),\qquad Q=O
$$

切断平面は次を満たします。

$$
(P-Q)\cdot N=0
$$

2ピクセル未満のドラッグは無視します。また、外積の長さの二乗が $10^{-12}$ 未満の場合も、安定した法線を作れないため処理を中止します。

### 3.3 ドラッグ範囲による受け入れ条件

数学的な平面は無限に広がるため、断面線分の両端を `IsInsideStroke()` で検査します。交点をワールド・ビュー・投影行列で変換し、一度だけ透視除算してスクリーン座標へ戻し、開始・終了点が作る軸平行矩形と比較します。各方向に2ピクセルの余白を設けています。

これは点とドラッグ線分との厳密な距離判定ではありません。現在は $w\leq10^{-5}$ の交点も除外します。いずれかの交線端点が条件を満たさなければ、そのサブセットは `Unchanged` となります。他のサブセットは独立して切断できる場合があります。

`Slice()` はこの判定をコールバックとして受け取ります。画面上の制約が不要な呼び出しでは、常に受け入れるオーバーロードを使用できます。

## 4. 切断平面のローカル空間への変換

描画と切断で同じワールド行列を使用します。行ベクトル規約における順序は：

$$
W=SRT
$$

現在のモデル姿勢には、Y 軸に $\pi$ を加える向き補正が含まれます。平面上の点と法線は異なる行列で変換します。

$$
Q_{local}=Q_{world}W^{-1}
$$

$$
N_{local}=\mathrm{normalize}(N_{world}W^T)
$$

一般に法線は「使用する座標変換行列の逆転置」で変換します。今回は座標変換が $W^{-1}$ なので：

$$
\left((W^{-1})^{-1}\right)^T=W^T
$$

となり、非一様スケールでも対応する平面への垂直性を維持します。ワールド行列が可逆であることを前提とし、ゼロスケールを有効な操作として扱いません。

## 5. 三角形入力と符号付き距離

`CutMeshes()` は `IndexArray` を通して頂点を参照し、3インデックスごとに展開三角形を生成します。インデックス配列の位置と頂点番号が同じとは仮定しません。

単位法線に対する符号付き距離は：

$$
d=(P-Q)\cdot N
$$

$d>0$ が正側、$d<0$ が負側です。既定の位置許容誤差は $\epsilon=10^{-4}$ で、$|d|\leq\epsilon$ の場合は判定用の距離をゼロにします。

これは分類値の変更であり、頂点そのものを平面へ移動しません。許容誤差はモデルのローカル単位に依存します。入力全体に正負両側の頂点が存在しない、または交線ノードがない場合は `Unchanged` を返します。

## 6. 半空間クリッピングと頂点属性

### 6.1 Clipを2回実行する

1回の `Clip()` は一方の半空間を残します。

$$
d\times side\geq0
$$

`side=+1` は正側、`side=-1` は負側です。平面上の頂点は両側の境界に含めます。元の境界順に辺 A→B を調べます。

| Aが残す範囲内 | Bが残す範囲内 | 追加する頂点 |
|---|---|---|
| はい | はい | A |
| はい | いいえ | A、交点 |
| いいえ | はい | 交点 |
| いいえ | いいえ | なし |

各辺は自分の始点を担当します。結果の凸多角形を、三角ファン $(P_0,P_i,P_{i+1})$ で分割します。

通常の横断では、単独頂点側に三角形、反対側に四角形ができ、後者を2つの三角形へ分割します。2回の呼び出しで両側を作ります。平面に横断されない三角形は、そのまま所属側へ入ります。

ここで三角ファンを使用できるのは、三角形を半空間で切った結果が凸だからです。凹形状になり得る断面の封口には、後段の耳切り法を使用します。

### 6.2 交点パラメーターと補間

辺の両端の距離を $d_A,d_B$ とすると：

$$
t=\frac{d_A}{d_A-d_B}
$$

$d(t)=d_A+t(d_B-d_A)=0$ を解いた式です。位置は：

$$
P=A+t(B-A)
$$

同じ $t$ で位置、UV、RGBA 頂点色、法線を線形補間し、補間法線は再正規化します。交点からの距離を使って比率を再計算しません。明示的に補間しない追加フィールドは A の値を引き継ぐため、接線やボーン属性の自動対応を意味しません。

### 6.3 三角形の登録条件

`Triangle()` は指定された頂点順を維持し、次を満たす面だけを追加します。

$$
\left\|(B-A)\times(C-A)\right\|^2>\epsilon^4
$$

外積の長さは面積の2倍なので、面積が $\epsilon^2/2$ を超える条件に相当します。退化面や微小面を除外しますが、一般的なメッシュ修復や閉鎖性の保証ではありません。平面上の頂点がクリッピング多角形内で重複した場合、それに伴うゼロ面積三角形もこの段階で除外します。

## 7. 断面交線と交点統合

表面クリッピングと封口用交線収集は別々の出力を持ちます。`Clip()` は両側の表面、各三角形の `hits` は断面交点です。現在は一部の交点・補間計算を重複して実行します。

平面上の元頂点を登録し、両端の距離が厳密に異符号となる辺では交点を補間します。異なる交点が2つあれば、その三角形が1本の断面線分を生成します。

| 処理 | 範囲 | 目的 |
|---|---|---|
| `AddUniqueIntersection()` | 1つの三角形 | 許容誤差内の交点を統合し、`hits`を数える |
| `FindOrAddCutNode()` | 現在のサブセット全体 | 隣接三角形の同じ交点に共通の番号を与える |
| 隣接登録の重複検査 | ノードの組 | 同じ無向交線の二重登録を防ぐ |

位置が同じでもノード番号が異なれば線分は接続されません。ノード統合は輪郭トポロジーの復元に必要です。位置統合は線形探索で、最初のノード属性を維持し、位置の平均化は行いません。

`hits` が0または1なら線分を登録せず、2なら登録します。3なら共面または曖昧なケースとして今回の切断を拒否します。これらの分類は許容誤差の影響を受けます。

### 7.1 既存辺に沿う切断と共面三角形

交点が2つあるだけでは、モデルを両側へ分割できるとは限りません。平面が既存辺を通る場合も2交点を得られ、残りの頂点は片側だけに存在し得ます。この辺は断面線分として利用できます。入力全体が平面の厳密な両側に頂点を持ち、交線が対応可能な閉輪郭を形成すれば、三角形内部を横切らなくても既存辺に沿って切断できる場合があります。外表面へ接するだけで両側に頂点がなければ、切断を適用しません。

非退化三角形の異なる3頂点がすべて平面上と分類される場合、3交点となり `OpenOrAmbiguousContour` を返します。これは現在維持している制限で、他の部分が両側に存在しても、共面三角形があれば今回のモデル更新を中止します。共面の面をどちらへ所属させるか、残すか置き換えるかは解決しません。

拒否までに `Clip()` が一時的な表面を生成している場合もありますが、それらは提出しません。共面三角形の拒否は、クリッピング出力が皆無という意味ではなく、操作全体を採用しないという意味です。

## 8. 隣接関係と閉じた輪郭

`nodes[i]` が交点、`adjacency[i]` が接続先番号です。線分 AB を A→B、B→A の両方向に記録します。

`BuildClosedContours()` は全ノードの隣接数が2であることを確認し、未訪問ノードから、直前ではない方の隣接ノードへ進みます。

- 開始点へ戻る：閉じた輪郭が完成。
- 開始点以外の訪問済みノードへ入る：失敗。
- 隣接数が2以外、または輪郭が3ノード未満：失敗。
- 未訪問ノードが残る：別の独立輪郭として処理。

各ステップで未訪問ノードを登録し、開始点または訪問済みノードで終了するため、有効なノード番号の下では無限巡回しません。隣接数2の確認は接続構造の検査であり、幾何学的自己交差の完全な検査ではありません。

## 9. 平面座標への投影と入れ子検査

単位法線とほぼ平行にならない参考軸 R を選びます。現在は $|N_x|<0.9$ で X 軸、それ以外で Y 軸を使用します。

$$
U=\mathrm{normalize}(R\times N),\qquad V=N\times U
$$

$U\times V=N$ となる基底で、交点を投影します。

$$
p_u=(P-Q)\cdot U,\qquad p_v=(P-Q)\cdot V
$$

`projected[i]` は `nodes[i]` と同じノードを表し、`loops` は順序付きノード番号を保持します。

`IsPointInsideContour()` は右向き水平レイと境界の交差回数の奇偶で内外を判定します。`HasNestedContours()` は各輪郭の代表ノードが別の輪郭の内部にあるか調べます。

輪郭が単純で、互いに交差・接触しないことを前提とする代表点判定です。完全な輪郭交差検査ではありません。入れ子を検出したら `UnsupportedHole` を返し、穴を塗りつぶした面で塞ぎません。

## 10. 頂点順と耳切り法

### 10.1 反時計回りへ統一

符号付き面積の2倍を求めます。

$$
A_2=\sum_i(x_i y_{i+1}-y_i x_{i+1})
$$

負なら順序を反転します。隣接巡回の開始方向は一定ではないため、耳切り前に反時計回りへ統一します。

### 10.2 耳の判定

隣り合う A、B、C に対して：

$$
Orient(A,B,C)=(B_x-A_x)(C_y-A_y)-(B_y-A_y)(C_x-A_x)
$$

反時計回りの輪郭では正値が凸角です。現在は $Orient>\epsilon^2$ の候補を使用します。

他の輪郭頂点 P が次をすべて満たすか検査します。

$$
Orient(A,B,P)\geq-\epsilon^2
$$
$$
Orient(B,C,P)\geq-\epsilon^2
$$
$$
Orient(C,A,P)\geq-\epsilon^2
$$

内部または許容誤差内の辺上に頂点があれば候補を除外します。なければ ABC を保存し、作業輪郭から B だけを削除します。残った輪郭で繰り返し、最後の3ノードも登録します。

輪郭はコピーして処理し、元のノード表は変更しません。n ノードの単純輪郭で成功すると n−2 個の三角形になります。耳が見つからない、または最後の三角形が面積条件を満たさなければ `TriangulationFailed` です。

`TriangulateContours()` の出力は `TriangleIndices`、すなわちノード番号の三つ組です。実際の封口頂点生成とは分離しています。

## 11. 両側の切断面、法線、UV

`AppendCapTriangles()` がノード番号から両側の切断面を生成します。`CreateCapVertex()` は位置や頂点色を引き継ぎ、法線とUVを上書きします。

| 側 | 切断面の外向き法線 | 頂点順 |
|---|---|---|
| 負側 $d\leq0$ | $+N$ | A、B、C |
| 正側 $d\geq0$ | $-N$ | C、B、A |

頂点順は幾何学的な向き、`Normal` は照明用属性を表すため、両方を設定します。元表面と切断面の境界は同じ位置でも別の法線を持ち、ハードエッジを表現します。

平面UVは：

$$
(UV_x,UV_y)=(p_u,p_v)\times uvScale
$$

既定の `uvScale=0.1` を使用し、断面全体を自動的に [0,1] へ正規化しません。範囲外の見え方はサンプラーと材質に依存します。切断面は元サブセットの材質を引き継ぎ、専用材質は生成しません。

最後に元表面と切断面を一緒に移動します。

$$
P_-=P-N\times separation,\qquad P_+=P+N\times separation
$$

既定値は各側1.5ローカル単位で、元々重なっていた切断面間は3単位離れます。完了時に `Status::Cut` を返し、生成された頂点が次の切断入力になります。

## 12. サブセットの一時保持とモデル更新

切断はサブセット単位です。`PendingSubset::primaryVertices` は常に存在し、切断時は負側、未切断時は元データを保持します。`additionalVertices` は切断時の正側です。これらは提出時の役割を表す名前で、常に幾何学的な側を表すわけではありません。

全サブセットをローカルの `pending` に保持します。

- `Cut`：両側の結果を保存。
- `Unchanged`：元サブセットを維持。
- その他のアルゴリズム失敗：モデル全体の更新を中止。
- 全サブセットが未変更：リソース再構築を行わない。

容量確認後、最終配列を更新キューへ渡します。`TryUpdateModel()` は非空配列を集計し、新しい展開頂点・連番インデックス・サブセットと材質を作成して、新しい頂点／インデックスバッファを確保します。全準備が成功した時点で旧モデルを解放し、新データを取り付けます。

新インデックスは 0、1、2…です。現在の16ビット形式では展開頂点数を65,535以下に制限するため、再切断を無制限に行えるわけではありません。

### 結果ステータス

| ステータス | 意味 |
|---|---|
| `Unchanged` | 今回の切断を採用せず、対象サブセットを維持 |
| `Cut` | 両側の表面と切断面の生成が完了 |
| `InvalidInput` | 切断入力または設定が現在の条件を満たさない |
| `OpenOrAmbiguousContour` | 開いた交線、分岐、共面、または輪郭復元が不明確 |
| `UnsupportedHole` | 未対応の入れ子輪郭を検出 |
| `TriangulationFailed` | 耳切りが完了しない、または最終三角形の面積条件を満たさない |

失敗結果に一時頂点が含まれても、完成したメッシュとして提出しません。

## 13. 所有権と失敗時の処理

| リソース | 管理方法 |
|---|---|
| 提出前のサブセット配列 | `unique_ptr<SimpleArray<VERTEX_3D>>` |
| 更新キューへ渡した一時配列 | `QueueCleanup` が終了時に削除・キューをクリア |
| 提出前のCPU配列 | `unique_ptr<T[]>` |
| 提出前のGPUバッファ | `BufferOwner` が失敗終了時に `Release()` |
| 提出済みモデル | `UnloadModel()` がテクスチャ参照、バッファ、配列、外側の `MODEL` を解放 |

材質キューのテクスチャポインターは借用で、キュー破棄時には `Release()` しません。新サブセットごとに旧モデル解放前に `AddRef()` し、旧サブセットの参照を解放しても共有テクスチャが有効な状態を維持します。

CPU配列の提出には `release()`、GPUバッファには提出後の所有者ポインターのクリアを使用します。局所的なクリーンアップ型は、実際にオブジェクトを生成して初めてデストラクターによる処理が働きます。

既存のアルゴリズムエラー、引数・容量拒否、メモリ確保失敗、バッファ作成失敗を扱います。任意の入力破損やすべての例外を回復する仕組みではありません。`SimpleArray` 内部の解放はコンテナーの既存デストラクター規約に依存します。

## 14. スナップショットと取り消し／やり直し

### 14.1 保存する状態

`ModelSnapshot` は頂点、インデックス、サブセットと材質の独立した配列を保存します。位置、法線、頂点色、UVに加え、以前の切断で生成された切断面や分離移動もモデル状態に含まれます。GPUバッファ、カメラ、表示用モデル変換、塗りつぶし設定、切断平面の表示設定は保存しません。

`Capture()` はCPU配列をディープコピーしますが、テクスチャ画素は複製しません。保存するサブセットごとにテクスチャへ `AddRef()` し、スナップショットの破棄時に対応する `Release()` を行います。コピーは禁止し、`unique_ptr<ModelSnapshot>` で所有します。

`Restore()` は保存したインデックスとサブセット範囲を維持してCPU配列を作成し、頂点／インデックスバッファを再作成します。切断用の一時キューを経由せず、幾何アルゴリズムも再実行しません。準備完了後、復元モデル用のテクスチャ参照を取得し、`UnloadModel()` で旧モデルを解放して置換します。メモリ確保やバッファ作成に失敗した場合、現在のモデルを維持します。

### 14.2 2つのスタック

`ModelHistory` は、取り消し用とやり直し用の2つの `std::stack<std::unique_ptr<ModelSnapshot>>` を使用します。現在表示中のモデルそのものをスタック先頭に置くのではなく、復元先となる他の状態を保存します。

| 操作 | 復元元 | 現在の状態の保存先 |
|---|---|---|
| 元に戻す | 取り消しスタックの先頭 | やり直しスタック |
| やり直す | やり直しスタックの先頭 | 取り消しスタック |

Aから2回の切断でCになった場合、現在はC、取り消しスタックは底からA、Bです。1回戻すと現在はB、取り消し側はA、やり直し側はCになります。さらに戻すと現在はA、やり直し側は底からC、Bとなり、やり直しではB、Cの順に復元します。

同じスナップショットをスタック間で移動する処理ではありません。Bを復元する際、反対側へ保存するのは直前に取得した現在状態Cです。

### 14.3 モデル更新と履歴の確定

切断アルゴリズムと容量確認の後、`PrepareCut()` で旧モデルを保存して取り消しスタックへ一時追加し、`TryUpdateModel()` でモデルを更新します。局所オブジェクト `CutHistoryGuard` が終了時に `FinishCut()` を呼びます。

更新成功時は記録を確定してやり直し履歴を破棄します。失敗時は一時記録だけを取り消し、やり直し履歴を維持します。未切断、アルゴリズム拒否、容量超過では履歴を追加しません。スナップショットを保存できなければ、切断結果も提出しません。

取り消し／やり直しでも、現在状態の取得と反対側への追加をモデル変更前に行います。追加時にメモリ確保が発生する可能性があるためです。復元失敗時は追加した記録を削除して復元元を残し、成功した場合だけ復元元を取り除きます。履歴なしは `S_FALSE`、復元成功は `S_OK` で、どちらもHRESULTの失敗ではありません。

別モデルの読み込み成功時は両履歴を消去し、読み込み失敗時は維持します。取り消し後に新しい切断が成功すると編集が分岐し、以前のやり直し履歴は破棄されます。終了時も明示的に履歴をクリアし、スナップショットとテクスチャ参照を解放します。

### 14.4 入力とリソース範囲

`Ctrl+Z` で元に戻し、`Ctrl+Y` または `Ctrl+Shift+Z` でやり直します。左右のCtrl／Shiftに対応し、Z／Yの押下開始を検出するため、押し続けても毎フレーム実行しません。切断線のドラッグ中は履歴操作を受け付けません。復元成功時は古い切断平面プレビューを無効化し、表示スイッチ、塗りつぶし設定、カメラは維持します。

履歴はメモリ上のみで、ファイルに保存しません。差分ではなくCPU形状全体を保存し、現在は件数やメモリ量の上限を設定していません。長時間編集では履歴に応じてメモリ使用量が増加します。テクスチャはCOM参照で共有し、画素や各履歴のGPUメッシュバッファを複製・保持し続けません。

## 15. OBJドロップとリセット

`DragAcceptFiles()` と `WM_DROPFILES` で単一OBJのパスを受け取り、メッセージ処理では要求だけを保存します。実際の同期読み込みは次の更新処理で行います。

ワイド文字パスはローダーが使う Windows ANSI コードページへ変換し、表現できない文字を拒否します。区切り文字を `/` に統一して関連ファイルを解決します。完全なUnicode対応ではなく、MTL／テクスチャの参照名は空白を避け、既存パーサーの形式に合わせることを推奨します。

`ReplacePlayerModel()` は一時モデルへ読み込み、成功した場合だけCPUデータと2つのGPUバッファを交換し、旧リソースを解放します。失敗時は表示中のモデルと履歴を維持します。成功時は取り消し／やり直し履歴を消去します。

成功後は位置・回転・拡大率、移動慣性、ドラッグ状態、切断平面データ、カメラを初期状態へ戻します。同じOBJを再ドロップすると未切断形状へ戻せます。Rは表示状態だけを戻し、形状を再読み込みしません。ドロップ操作を切断と誤認しないよう、ドラッグを取り消して左ボタンの解放を待ちます。

読み込みは同期処理で、バックグラウンドスレッドは使用しません。モデルの自動センタリングやサイズに応じたカメラ調整も行いません。

## 16. 表示モードと操作ガイド

F1で `D3D11_FILL_SOLID / D3D11_FILL_WIREFRAME` を切り替えます。塗りつぶし2種類とカリング3種類の計6状態を事前作成し、両方の選択を記録して適用するため、`SetCullingMode()` がワイヤーフレーム設定を上書きしません。

F3で切断平面を表示／非表示にします。頂点バッファへの書き込み成功も必要で、最初の有効なドラッグ前は未初期化の平面を描きません。プレビューは2本のレイ上の距離15と300の点から作る四角形で、この距離は数学的切断範囲を制限しません。

プレビューは最後に作成を試みた平面を表し、切断が拒否された場合も更新されることがあります。モデルのリセットや取り消し／やり直しの成功時に古い平面を無効化し、表示設定は維持します。現在の塗りつぶし設定はプレビューにも適用されます。

`PrintDebugProc()` で毎フレーム操作ガイドを登録し、`DrawDebugProc()` から `DebugTextOut()` を呼び出して描画します。F1／F3の状態と履歴ショートカットはDebug／Releaseの両方で表示します。`DEBUG_DISP_TEXTOUT` を有効にした構成でBGRAバックバッファとGDI互換スワップチェーンを使用し、D3DデバッグレイヤーはDebugでのみ有効にします。カメラの旋回、上下移動、接近／後退、およびRキーによるリセットはDebug／Releaseの両方で有効です。

| 入力 | 操作 |
|---|---|
| 左ドラッグ後に解放 | 切断を試行 |
| 単一OBJのドロップ | モデル置換とリセット。成功時に履歴を消去 |
| Ctrl + Z | 元に戻す |
| Ctrl + Y / Ctrl + Shift + Z | やり直す |
| F1 | 塗りつぶし／ワイヤーフレーム |
| F3 | 切断平面の表示／非表示 |
| 矢印キー | カメラ方向を基準にモデルを移動 |
| A / D | カメラの水平旋回 |
| W / N | カメラの上昇／下降 |
| U / M | カメラの接近／後退 |
| R | モデル姿勢とカメラをリセット。形状は維持 |
| Esc | 終了 |

カメラ旋回はA／D、上昇はWを使用し、Z／Yを使用しません。カメラ側でCtrlとの競合を判定する必要はありません。

## 17. 実行環境と制限

Windows上のVisual Studioプロジェクトで構築し、使用するDirectX 11、DirectXMath、入力、D3DX11の依存関係を用意します。現在のC++17設定を使用し、Shader／アセットの相対パスと作業ディレクトリーを一致させます。OBJは三角形化済みで、法線・UV・明示的な材質グループ・有効な参照ファイルを持つ形を推奨します。

- 封口対象の各サブセット内で交線が閉じる必要があります。材質分割により1つの閉じた物体が開いた面へ分かれると、切断を拒否する場合があります。
- 単純な凹輪郭に対応しますが、穴、自己交差処理、一般的なメッシュ修復には対応しません。
- 異なる3頂点が平面上と分類される共面三角形は、他の部分が両側に存在しても更新全体を拒否します。微小形状や許容誤差による不正な統合も拒否の原因になります。拒否は修復を意味しません。
- 履歴はCPU形状全体を保持し、現在は件数／メモリ量の制限や永続化を提供しません。
- ワイヤーフレームは三角形の辺を表示し、物体の外形だけを描くアウトラインではありません。
- 曲線の刃、任意の立体ブーリアン、コリジョン、剛体運動は対象外です。
- ノード統合は線形探索です。候補耳を繰り返し探し、他頂点を走査する実装は最悪で三乗の計算量となり得ます。大規模メッシュ向けの最適化完了を主張しません。
- 16ビット容量、モデルスケール、許容誤差が再切断の細かさと安定性を制約します。

推奨デモ順序：立方体の平切り・斜め切り → 連続取り消し／やり直し → 取り消し後の再切断で分岐確認 → L字プリズムの凹断面 → F1で分割確認 → F3で平面確認 → 再ドロップで元形状へ復帰し履歴を消去。
