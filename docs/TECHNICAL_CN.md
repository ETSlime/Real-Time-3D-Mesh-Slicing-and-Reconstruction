# Mesh Cut：技术说明

[项目主页](../README_CN.md) · **中文** · [日本語](TECHNICAL_JP.md) · [English](TECHNICAL_EN.md)

## 1. 项目与功能范围

Mesh Cut 是一个基于 C++、DirectX 11 和 DirectXMath 的交互式网格切割演示。用户在窗口中拖动鼠标，由起终点生成三维切割平面。系统在 CPU 上裁剪三角形，对闭合体恢复轮廓并封口，对开放表面只裁剪，最后重建绘制资源。

当前支持平面切割、交点属性插值、闭合体的简单凹轮廓封口、多个独立非嵌套截面、开放表面不封口切割以及重复切割。运行时可以拖入 OBJ 更换模型，通过 F1 切换实心／线框，通过 F3 显示／隐藏切割平面；通过双栈快照历史撤销和重做切割。操作提示在 Debug 与 Release 中均显示。

“切开”意味着重新生成三角形表面并分离两侧的位置，不包含碰撞体生成、刚体模拟或切块物理行为。

## 2. 模块与数据流

| 模块 | 职责 |
|---|---|
| `main.cpp` | 接收拖放请求、处理显示模式按键、驱动更新与绘制 |
| `ObjImporter` | 读取 OBJ／MTL，生成顶点、索引、subset 与材质数据 |
| `player.cpp` | 鼠标交互、平面转换、调用几何算法、暂存并提交模型结果 |
| `MeshCutter` | 数学辅助、属性插值、表面裁剪、交线组织、轮廓三角化与封口 |
| `ModelSnapshot.h / .cpp` | 独立模型快照、纹理引用持有、CPU／GPU 状态恢复 |
| `ModelHistory.h / .cpp` | 两个历史栈、切割记录提交、撤销／重做与清空 |
| `renderer.cpp` | DirectX 资源、绘制状态、填充模式与剔除模式组合 |
| `camera.cpp` | 透视相机、矩阵更新与初始状态恢复 |

`MeshCutter.h` 声明类型与接口；非模板方法定义于 `.cpp`；模板定义置于 `.inl`，由头文件末尾包含。几何计算使用 CPU 数据，但当前 `MeshCutter` 也提供 DirectXMath 坐标辅助函数，并非完全不依赖 DirectX 的公共头文件。

切割流程分为：

1. 屏幕拖动生成世界空间平面。
2. 将平面转换到模型局部空间。
3. 按索引展开各 subset 的三角形，按持久碎块编号组织输入。
4. 在同一碎块内跨材质裁剪表面，共享交点并收集截面线段。
5. 合并切口节点；闭合体恢复闭环并投影到二维。
6. 闭合体检查轮廓嵌套并耳切封口；开放表面跳过封口。
7. 设置封口属性，仅分离切开的碎块，验证最终连接并生成新编号。
8. 暂存全部 subset，保存切割前快照，准备新 CPU／GPU 资源，成功后提交模型与历史。

## 3. 屏幕拖动与世界空间切割平面

### 3.1 从屏幕坐标构造射线

窗口坐标 $(s_x,s_y)$ 先转换为标准化设备坐标：

$$
x_{ndc}=\frac{2s_x}{w}-1,\qquad y_{ndc}=1-\frac{2s_y}{h}
$$

其中 $w,h$ 为当前实现使用的 `SCREEN_WIDTH / SCREEN_HEIGHT`。Y 方向翻转是因为窗口坐标向下增大，而投影坐标向上增大。

对于当前常规对称透视投影，垂直视场角为 $\theta_y$、宽高比为 $a$：

$$
P_{11}=\frac{1}{\tan(\theta_y/2)},\qquad P_{00}=\frac{P_{11}}{a}
$$

在观察空间取 $z=1$，得到射线方向：

$$
D_{view}=\left(\frac{x_{ndc}}{P_{00}},\frac{y_{ndc}}{P_{11}},1\right)
$$

`CreateWorldRayDirection()` 使用逆视图矩阵变换方向并归一化。方向不受相机平移影响；射线起点则通过将观察空间原点变换到世界空间取得。

这里的下标从零开始：$P_{00}$ 和 $P_{11}$ 分别是投影矩阵的 X、Y 缩放项。若两者均为 1，则对应垂直视场角 $90^\circ$、宽高比 1 的对称透视模型，并非正交投影。方向用 `w=0` 构造，并通过 `XMVector3TransformNormal()` 变换；相机平移不参与方向变换。

省略除以 $P_{00}/P_{11}$ 并不会变成正交射线。它仍是从同一起点发散的方向，只是相当于使用不匹配的投影参数。当前公式不用于正交或偏心投影，也假定鼠标映射与全窗口视口一致。

### 3.2 两条射线确定平面

拖动起终点对应单位方向 $D_s,D_e$，共享相机起点 $O$：

$$
N=\mathrm{normalize}(D_e\times D_s),\qquad Q=O
$$

平面满足：

$$
(P-Q)\cdot N=0
$$

屏幕拖动短于 2 像素时不执行切割；叉积长度平方小于 $10^{-12}$ 时也不继续归一化。这些是当前实现的数值保护阈值。

### 3.3 拖动范围接受条件

平面在数学上无限延伸，因此每条截面线段的端点还会通过 `IsInsideStroke()` 检查。交点经模型、观察、投影矩阵得到齐次坐标，执行一次透视除法后返回屏幕坐标，再与拖动起终点构成的轴对齐矩形比较，矩形各方向增加 2 像素余量。

它不是严格的点到拖动线段距离检测。当前实现还拒绝 $w\leq10^{-5}$ 的交点。某条有效截面线段的端点不满足条件时，当前碎块返回 `Unchanged`；其他碎块仍可独立切割。接受条件作用于整个碎块的切口，不按材质分别决定。

`SliceModel()` 接受一个回调，用于执行这项交互条件；不需要屏幕范围限制时，可以传入始终返回 true 的回调。

## 4. 世界空间到模型局部空间

绘制与切割使用相同世界矩阵，采用行向量约定：

$$
W=SRT
$$

模型旋转包含当前项目的 Y 轴额外 $\pi$ 朝向修正。平面上的点和法线转换方式不同：

$$
Q_{local}=Q_{world}W^{-1}
$$

$$
N_{local}=\mathrm{normalize}(N_{world}W^T)
$$

一般法线规则是“对当前坐标变换矩阵取逆转置”。此处坐标变换为 $W^{-1}$，因此法线矩阵为：

$$
\left((W^{-1})^{-1}\right)^T=W^T
$$

这样在非均匀缩放下仍能保持法线与对应平面垂直。该过程假定世界矩阵可逆，不将零缩放作为有效操作。

## 5. 输入三角形、碎块与有符号距离

`CutMeshes()` 通过 `IndexArray` 取出展开三角形，并将所有材质 subset 一起交给 `SliceModel()`。subset 表示绘制材质分组，不表示独立的封闭几何体；同一碎块可以跨越多个 subset。

首次处理时，`InitializePieceIds()` 根据跨材质的几何连接建立碎块编号。此后按每个三角形保存的持久编号组织输入，而不是在整个场景中重新按位置连接。这样，分离后相互重叠的不同碎块不会被重新合并；只切中中间一块时，其他碎块仍保留原位置、属性与编号。

每个碎块内部建立共享位置编号。单位切割平面法线下：

$$
d=(P-Q)\cdot N
$$

$d>0$ 为正侧，$d<0$ 为负侧。法线是切割平面的法线，不是各个模型表面的光照法线，因此所有 subset 共用同一个平面。默认位置容差为 $\epsilon=10^{-4}$，以模型局部单位计。共享位置的距离以 double 计算；$|d|\leq\epsilon$ 时分类为零，并将输出使用的共享位置投影到平面。输入数组本身不被修改。

当前碎块没有严格位于两侧的顶点时，不采用切割结果。位置容差需要结合资产尺度理解，不能视为任意模型的统一精度保证。

### 5.1 开放表面与闭合体的自动分类

共享位置编号和边连接检查也用于 `ClassifyInputSurface()`。在每次切割的当前有效容差下，按独立连接成分、跨材质统计无向边：所有边由两面共享时按闭合体处理，并检查共享边方向一致性；存在只由一面使用的边时按开放表面处理。三面以上共边或坍缩连接仍拒绝，不作为开放边放行。

`SliceComponentAttempt()` 对两类输入复用同一表面裁剪与交线接受条件。闭合体继续恢复闭环并封口；开放表面跳过闭环、孔检查和封口，只输出分离后的表面，仍需有效切口及两侧非空结果。同一刀命中两类成分时分别处理，再统一提交，任一算法失败仍取消整次更新。封口失败不会自动降级为开放表面。

`AssignSidePieceIds()`／`AssignNewPieceIds()` 将 `requireClosed` 传给既有连接检查：闭合体的结果要求闭合，开放表面允许边界。无需增加持久字段或改动快照格式。独立形状编号现在可代表开放或闭合的连接表面，不一定有体积。

分类依据实际边界，无法区分有意制作的薄片与漏面的壳；两者均按开放表面处理。开放表面保留各原面朝向，不自动统一绕序或修复法线。

## 6. 半空间裁剪与交点属性

### 6.1 分别保留两个半空间

`ClipSubset()` 处理一个材质组的三角形；`AppendClippedTriangle()` 分别输出两侧。每次只保留满足下式的顶点：

$$
d\times side\geq0
$$

`side=+1` 保留正侧，`side=-1` 保留负侧，平面上的顶点属于两侧边界。沿原三角形边界 A→B 依次处理，下表先描述两端不在平面上的普通情况：

| A 在本次保留范围 | B 在本次保留范围 | 当前边追加的顶点 |
|---|---|---|
| 是 | 是 | A |
| 是 | 否 | A、交点 |
| 否 | 是 | 交点 |
| 否 | 否 | 无 |

平面上的原顶点在自己的起点步骤加入；只有两端距离严格异号时才生成新的边内交点，避免将原端点再次插值加入。两侧复用预先计算的交点。

结果保持原边界顺序，是凸多边形，可以用三角扇 $(P_0,P_i,P_{i+1})$ 拆分。普通横穿时，单独顶点侧得到一个三角形，另一侧得到四边形并拆成两个三角形。未横穿的原三角形进入所属侧。这里的三角扇只负责裁剪后的原表面，凹形截面的封口使用后面的耳切法。

### 6.2 插值参数与共享位置

边端点有符号距离为 $d_A,d_B$，沿边距离满足 $d(t)=d_A+t(d_B-d_A)$。令其为零：

$$
t=\frac{d_A}{d_A-d_B},\qquad P=A+t(B-A)
$$

同一个参数用于位置、UV、RGBA 顶点色和法线的线性插值，插值法线再归一化。端点参数为 0 或 1 时直接返回对应原顶点，避免插值公式产生不同于原端点的浮点结果。

`InterpolateSharedEdge()` 按统一端点顺序，以 double 计算交点位置，并缓存到共享边编号。原表面与封口引用同一代表位置；各材质／三角形的法线、UV 和颜色仍从自己的绘制顶点插值，不因位置共享而抹平接缝。额外且未显式处理的顶点字段继承端点 A，不代表自动支持切线或骨骼属性。

### 6.3 三角形登记

`Triangle()` 保持调用者给出的绕序，以 double 计算叉积，过滤实际零面积三角形。不会单纯因为面积小于位置容差平方就独立删除有效小面，以免在相邻表面之间留下缺口。非零面积仍不足以证明网格有效，最终结果还需要闭合连接检查。

## 7. 截面线段与共享拓扑

原表面三角形和封口轮廓是两份不同输出，但共享求交结果。`ClipSubset()` 中的 `hits` 保存当前三角形触及的切割节点编号；它不是封口三角形，也不是整个闭环。`AppendUniqueIndex()` 去除重复节点编号。

| 层次 | 标识与作用 |
|---|---|
| 共享原顶点 | 使用共享位置编号，对相邻三角形进行一致的平面分类 |
| 边内交点 | 使用无向端点编号对，缓存同一条边的交点位置 |
| 切割节点 | 容差内统一代表位置，供原表面和封口共同使用 |
| 截面线段 | 使用无向节点对，累计相邻面位于平面的哪一侧 |

### 7.1 真正切口与同侧接触

普通穿过三角形内部的线段直接具有正负两侧信息。平面经过已有边时，单个三角形只能提供一侧信息；等同一碎块的所有材质组处理完成，再合并这条边两侧的标记。只有同时出现正侧和负侧的边才进入轮廓邻接表；两邻面都在同侧的边只是接触，不作为切口。仅触及一个顶点的孤立节点不要求组成闭环。

因此，已有边切割可以成功，外表面相切则可返回 `Unchanged`。真正分割中出现整三角形共面或不能唯一确定的退化连接时，仍可能拒绝本次更新。所有临时输出均在验证通过后才采用。

## 8. 邻接关系与闭环恢复

`nodes[i]` 保存交点，`adjacency[i]` 保存连接到它的其他节点编号。每条线段 AB 双向登记 A→B、B→A。

以下闭环要求只用于闭合体封口，开放表面无需闭环。忽略不属于有效截面线段的零邻居接触节点后，正常闭合截面要求每个参与节点恰好有两个邻居。`BuildClosedContours()` 从未访问节点出发，记录当前节点，再选择不是上一节点的另一个邻居，直至回到起点。

- 回到当前起点：完成闭环。
- 提前进入其他已访问节点：失败。
- 邻居数量不为 2，或轮廓少于 3 个节点：失败。
- 外层继续寻找未访问节点：恢复其他独立轮廓。

循环每次登记一个新节点，回到起点或遇到已访问节点就退出，因此在有效编号前提下不会无限遍历。两个邻居只证明连接结构符合闭环要求，不完整检测几何自交。

## 9. 平面二维坐标与嵌套检查

二维投影及方向判断使用 double 中间量。选择不接近平行于单位法线的参考轴 $R$：当前规则在 $|N_x|<0.9$ 时选 X 轴，否则选 Y 轴。构造：

$$
U=\mathrm{normalize}(R\times N),\qquad V=N\times U
$$

其中 $U\times V=N$。将节点投影：

$$
p_u=(P-Q)\cdot U,\qquad p_v=(P-Q)\cdot V
$$

`projected[i]` 与 `nodes[i]` 编号保持一致，`loops` 只存储有序节点编号。

`IsPointInsideContour()` 使用向右水平射线的奇偶规则：跨越边界奇数次为内部，偶数次为外部。`HasNestedContours()` 取每个轮廓的一个节点，检查它是否位于另一轮廓内部。

该代表点判断假定各轮廓简单、互不交叉且不接触，不是全面的轮廓相交检测。检测到嵌套时返回 `UnsupportedHole`，不尝试把孔填成实心面。

## 10. 绕序与耳切三角化

### 10.1 统一逆时针

二维有向面积的两倍为：

$$
A_2=\sum_i(x_i y_{i+1}-y_i x_{i+1})
$$

负值时反转轮廓，统一为逆时针。实际计算以轮廓首点为相对原点累加，减少较大坐标间的抵消误差。

### 10.2 选择耳朵

对相邻节点 A、B、C：

$$
\mathrm{Orient}(A,B,C)=(B_x-A_x)(C_y-A_y)-(B_y-A_y)(C_x-A_x)
$$

逆时针轮廓中，正值表示凸角。候选必须具有可靠的正方向，并且不能包含其他轮廓顶点；否则切下它会越过边界或覆盖其他部分。有效候选中优先选择最小高度更大的三角形，减少狭长小面。保存 ABC 后，只从工作轮廓删除 B，继续处理剩余轮廓。

方向与点在三角形内的判断使用 double 及与行列式运算量相关的误差界，不将位置容差平方直接当作通用方向阈值。每个轮廓使用副本，原节点保留；n 个边界节点的简单轮廓成功分割后生成 n−2 个三角形。没有可用耳朵或分割无法完成时返回 `TriangulationFailed`。

`TriangulateContours()` 输出 `TriangleIndices`，只保存三元节点编号，与后续生成封口顶点分离。

### 10.3 边界保留与数值稳定性

近共线边界可暂时简化以改善耳切质量，但被省略的边界节点必须重新插回三角网格，保持封口与原表面的边界分段一致。内部边在不改变边界的前提下可进行有限次改善，避免用删除短边的方式掩盖连接错误。

分离偏移写回 float 后，检查封口朝向；必要时按实际移动后的坐标重三角化。旧平面表面只有满足参考朝向、近共面、统一法线以及近似仿射 UV／一致顶点色条件时才允许自动重建，避免破坏有意义的属性接缝。

若当前碎块返回 `OpenOrAmbiguousContour` 或 `TriangulationFailed`，可在原输入与同一平面上最多两次减半位置容差重试；细化受 float 坐标间隔与距离计算误差下限约束。不会移动切割平面，也不对 `Unchanged`、无效输入或孔进行这种重试。

## 11. 两侧封口、法线与 UV

仅对闭合体，`AppendCapTriangles()` 根据节点编号生成两侧封口。`CreateCapVertex()` 复制交点位置与颜色等字段，再覆盖切面法线和 UV。

| 切块 | 封口外法线 | 三角形顺序 |
|---|---|---|
| 负侧 $d\leq0$ | $+N$ | A、B、C |
| 正侧 $d\geq0$ | $-N$ | C、B、A |

绕序控制几何朝向；`Normal` 字段控制保存的光照法线，两者分别设置。原表面边缘与切面边缘可以位于同一位置，但使用不同法线，形成清晰硬边。

平面 UV 为：

$$
(UV_x,UV_y)=(p_u,p_v)\times uvScale
$$

默认 `uvScale=0.1`，不自动将截面归一化到 [0,1]；超出范围后的效果由采样器和材质决定。封口独立输出，由应用选择现有材质，不创建专用切面材质；跨材质轮廓不要求按各原材质边界划分封口。

对实际切开碎块的每侧原表面与封口统一偏移；未切碎块不动：

$$
P_-=P-N\times separation,\qquad P_+=P+N\times separation
$$

默认每侧移动 1.5 个局部单位，因此两侧原本重合的切面间距为 3 个局部单位。完成后返回 `Status::Cut`。偏移发生在 CPU 顶点中，后续切割直接处理这些结果。

## 12. 碎块结果、材质暂存与模型更新

`SliceModel()` 在每个持久碎块内跨 subset 组织轮廓。`ModelResult::subsets` 按原材质组保存切开表面，`caps` 单独保存封口，`unchangedSubsets` 保存未切碎块，并携带每个三角形的碎块编号。闭合体的单个材质组无需独立形成闭环；开放表面的 `caps` 为空，编号与表面按同一接口输出。

- `Cut`：采用新表面和闭合体所需的封口，只分离实际切开的成分。
- 碎块 `Unchanged`：保留该碎块原始几何、属性和编号，不施加分离偏移。
- 任一碎块出现其他失败：放弃整次模型更新，不提交部分成功结果。
- 全部未变化：不重建资源、不增加历史。

最终分离坐标下，闭合体要求每条无向边恰好由两个面共享；开放表面允许一面使用的边界，仍拒绝三面以上共边。新碎块编号与几何一起暂存，更新成功才写入模型。

`CutMeshes()` 保留原表面与材质的对应关系，封口使用现有材质，不生成专用切面材质。容量检查通过后交给 `TryUpdateModel()`，创建新的展开顶点、顺序索引、subset／材质表和独立 GPU 缓冲；全部准备成功后才释放旧模型。当前 16 位表示限制为最多 65,535 个展开顶点。

| 状态 | 含义 |
|---|---|
| `Unchanged` | 不采用切割，保留原碎块或模型 |
| `Cut` | 新表面、所需封口和独立形状编号准备完成 |
| `InvalidInput` | 输入格式、编号或设置不满足要求 |
| `OpenOrAmbiguousContour` | 闭合体轮廓未闭合，或分叉、共面歧义、生成连接无效；不表示所有开放表面都被拒绝 |
| `UnsupportedHole` | 检测到不支持的嵌套轮廓 |
| `TriangulationFailed` | 轮廓分割或所需的安全重三角化未能完成 |

这些是算法结果；顶点容量超限和 GPU 资源创建失败属于应用提交阶段的拒绝。失败不安装临时几何，也不增加有效切割历史。

## 13. 资源所有权与失败处理

| 阶段／资源 | 管理方式 |
|---|---|
| 尚未提交的 subset 数组 | `unique_ptr<SimpleArray<VERTEX_3D>>` |
| 已交给更新队列的临时数组 | `QueueCleanup` 离开函数时删除并清空记录 |
| 尚未安装的 CPU 数组 | `unique_ptr<T[]>` |
| 尚未安装的 GPU 缓冲 | 局部 `BufferOwner`，失败退出时 `Release()` |
| 已安装的模型 | `UnloadModel()` 释放纹理引用、缓冲、数组及外层 `MODEL` |

临时材质队列借用原纹理指针，不额外释放纹理。最终每个新 subset 在释放旧模型前为纹理增加一次 `AddRef()`，之后旧 subset 释放原引用，使共享纹理在替换期间保持有效。

成功交接 CPU 数组时使用 `release()`；交接 GPU 缓冲后将临时所有者指针置空。局部清理对象必须实际创建，只有类型声明不会执行析构。

该路径处理已有的算法返回、参数／容量拒绝、内存分配失败和缓冲创建失败，不是对所有导入错误或所有可能异常的完整恢复系统。`SimpleArray` 内部缓冲的释放依赖容器自身既有析构约定。

## 14. 快照与撤销／重做

### 14.1 快照保存什么

`ModelSnapshot` 保存独立的顶点数组、索引数组和 subset／材质数组。顶点中的位置、法线、颜色、UV，以及之前切割生成的封口和分离偏移，都属于保存的模型状态。快照也保存逐三角形的 `TrianglePieceIds` 和 `NextPieceId`，使撤销／重做恢复相同的碎块身份。快照不保存 GPU 缓冲，也不记录相机、模型展示变换、填充模式或切割平面显示开关。

`Capture()` 深拷贝 CPU 数组，但不复制纹理像素。每个保存的 subset 为其纹理调用一次 `AddRef()`；快照析构时，对应调用 `Release()`。快照禁止复制，由 `unique_ptr<ModelSnapshot>` 独占管理。

`Restore()` 根据快照复制新的 CPU 数组，保留保存的索引和 subset 范围，再创建顶点缓冲与索引缓冲。它不需要通过切割暂存队列，也不重新执行几何算法。全部资源准备成功后，先为恢复后的模型取得独立的纹理引用，再通过 `UnloadModel()` 释放旧模型并安装新资源。分配或缓冲创建失败时，当前模型保持原样。

### 14.2 两个栈

`ModelHistory` 使用两个 `std::stack<std::unique_ptr<ModelSnapshot>>`：撤销栈与重做栈。当前模型不直接保存在任一栈顶；栈中保存的是可恢复的其他状态。

| 操作 | 恢复来源 | 当前状态保存到 |
|---|---|---|
| 撤销 | 撤销栈顶 | 重做栈 |
| 重做 | 重做栈顶 | 撤销栈 |

例如 A 经两次成功切割变成 C：当前显示 C，撤销栈从底到顶为 A、B。撤销后显示 B，撤销栈剩 A，重做栈为 C。再次撤销显示 A，重做栈从底到顶为 C、B；重做时先恢复 B，再恢复 C。

一次撤销并不是把同一快照从一个栈搬到另一个栈。恢复源保存 B，而放入另一栈的是刚刚捕获的当前状态 C。

### 14.3 历史与模型一起提交

成功切割的处理顺序为：完成算法和容量检查 → `PrepareCut()` 捕获旧模型并临时压入撤销栈 → `TryUpdateModel()` 尝试替换模型 → `FinishCut()` 确定历史结果。局部 `CutHistoryGuard` 保证离开作用域时执行收尾。

更新成功时保留临时撤销记录并清空重做栈；更新失败时弹出临时记录，原有重做历史保留。未切中、算法拒绝或容量拒绝发生在历史准备之前，不增加记录。如果快照无法保存，则不继续提交切割。

撤销／重做时也先捕获当前状态，并在改变模型前压入目标栈，因为入栈可能分配内存。恢复失败就弹出刚加入的记录，恢复源保持不动；恢复成功才弹出恢复源。空历史返回 `S_FALSE`，实际恢复成功返回 `S_OK`，二者都不属于 HRESULT 失败。

成功导入另一个模型会清空两个栈；导入失败保留历史。撤销后再成功切割会建立新的编辑分支，原重做记录随之销毁。退出时显式清空历史，及时释放快照及其纹理引用。

### 14.4 输入与资源边界

`Ctrl+Z` 撤销；`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做，左右 Ctrl／Shift 均可。输入检测 Z／Y 的按下边沿，按住不会逐帧重复执行；拖动切割线期间忽略历史快捷键。成功恢复后清除旧切割平面预览，但不改变预览显示开关、填充模式或相机。

历史保存在内存中，不写入文件。每份快照都保存完整 CPU 几何，不是差量记录；当前没有历史条数或内存预算上限。长时间编辑的内存占用会随历史增长。纹理以 COM 引用共享，历史不重复保存纹理像素，也不长期保存每一步的 GPU 网格缓冲。

## 15. OBJ 拖放与状态恢复

窗口通过 `DragAcceptFiles()` 和 `WM_DROPFILES` 接收单个 OBJ 路径；消息阶段只保存请求，下一帧更新时执行同步加载。

宽字符路径转换为加载器使用的 Windows ANSI 代码页；不可表示的字符会被拒绝。目录分隔符统一成 `/`，供现有相对资源路径处理使用。这不等于完整 Unicode 导入。内部引用的 MTL／贴图文件名建议避免空格，文件需满足现有解析器的格式要求。

`ReplacePlayerModel()` 先加载临时模型，成功才交换 CPU 数据和两个 GPU 缓冲，随后释放旧资源。失败时保留当前模型和历史。成功替换后清空撤销栈与重做栈。

成功替换后，位置、旋转、缩放、移动惯性、拖动状态、切割平面数据和相机恢复初始状态；重新拖入同一 OBJ 可以恢复未切割几何。R 仅恢复展示状态，不重新读取几何。拖放手势会被取消并等待左键释放，避免意外触发一次切割。

加载是同步的，没有后台线程。新模型不自动居中或按包围盒调整相机距离。

## 16. 显示模式与操作提示

F1 切换 `D3D11_FILL_SOLID / D3D11_FILL_WIREFRAME`。渲染器预创建两种填充方式与三种剔除方式共六种状态；记录当前填充、剔除选择，通过组合绑定状态，避免 `SetCullingMode()` 覆盖线框设置。

F3 控制切割平面显示。显示还要求预览顶点缓冲已成功写入；首次有效拖动前不绘制未初始化平面。预览用两条射线在距离 15 与 300 处的四个点组成四边形，这些距离只决定显示形状，不限制数学切割平面。

预览展示最近尝试生成的平面，即使几何切割未被接受也可能更新。模型重置和成功的撤销／重做会清除旧预览，但保留显示开关。当前填充方式也会影响预览。

`PrintDebugProc()` 登记每帧操作提示，`DrawDebugProc()` 调用 `DebugTextOut()` 绘制。F1／F3 状态和撤销／重做组合键在 Debug 与 Release 中均显示。`DEBUG_DISP_TEXTOUT` 控制文字绘制支持；启用时使用 BGRA 后缓冲与 GDI 兼容交换链。D3D 调试层仍只在 Debug 中启用。相机操作与 R 重置也在 Debug 和 Release 中有效。

| 操作 | 功能 |
|---|---|
| 鼠标左键拖动并释放 | 尝试切割 |
| 拖入单个 OBJ | 替换并重置；成功后清空历史 |
| Ctrl + Z | 撤销 |
| Ctrl + Y / Ctrl + Shift + Z | 重做 |
| F1 | 实心／线框 |
| F3 | 切割平面显示／隐藏 |
| 方向键 | 相对相机朝向移动模型 |
| A / D | 相机水平旋回 |
| W / N | 相机升高／降低 |
| U / M | 相机靠近／远离 |
| R | 模型变换与相机重置，不恢复几何 |
| Esc | 退出 |

相机旋回使用 A／D、上移使用 W，不再占用 Z／Y，因此相机无需增加 Ctrl 冲突判定。

## 17. 运行环境、成本与当前限制

在 Windows 的 Visual Studio 项目中以 C++17 构建，配置 DirectX 11、DirectXMath、输入及 D3DX11 依赖，确保 Shader／资产相对路径与工作目录匹配。OBJ 应预先三角化，提供法线、UV 与有效 MTL／贴图引用。

| 范围 | 当前约束 |
|---|---|
| 输入几何 | 支持闭合体与开放表面；闭合体检查共享边绕序，开放表面保留输入朝向。边界分类不区分有意薄片与漏面壳；不自动修复、补厚或保证检测全部自交 |
| 截面 | 支持简单凹轮廓及多个独立非嵌套闭环；不支持孔、曲线刀面或任意实体布尔运算 |
| 退化与尺度 | 相切可未变化，实际分割中的整面共面或歧义连接可拒绝；float 顶点和有限容差不保证任意尺度、极窄特征或无限次切割，容差内投影／合并不保证保留更小细节 |
| 属性保护 | 若修复必须跨越超出允许误差的 UV 接缝、非仿射 UV 或非一致顶点色，可拒绝修复；不表示一般多材质或 UV 接缝不受支持 |
| 碎块身份 | 已识别碎块用编号保持独立；首次导入仍按几何识别连接，不保证重合输入的独立身份，不进行碰撞或重叠碎块求并 |
| 容量与历史 | 应用最多 65,535 个展开顶点；完整 CPU 快照随历史增长，尚无历史预算或持久化；此容量不是 D3D11 的通用上限 |

成本方面，裁剪主体按三角形遍历，共享边／线段使用映射，位置匹配仍含线性搜索。对 n 点轮廓，耳切的候选检查最坏可达 $O(n^3)$；边界恢复、质量改善和有限重试增加额外开销，不能把整个处理过程宣称为线性。临时内存随输入、生成三角形、拓扑映射与轮廓增长；模型替换期间同时持有旧、新资源，历史还独立保存 CPU 几何和编号，纹理以引用共享。

验证覆盖多材质模型、凹截面、已有边／顶点、局部碎块、重叠身份及连续切割；新增单平面、角色开放表面和开放／闭合混合用例，检查表面面积、属性和编号；闭合体另检查闭合、绕序及体积误差。测试通过说明这些用例中的行为，不代表所有输入均能成功。

建议演示顺序：立方体切割 → 多材质跨组封口 → L 棱柱凹截面 → 只切中间碎块 → 撤销／重做与编辑分支 → F1／F3 检查 → 重新拖入 OBJ。
