# Mesh Cut：技术说明

[项目主页](../README_CN.md) · **中文** · [日本語](TECHNICAL_JP.md) · [English](TECHNICAL_EN.md)

## 1. 项目与功能范围

Mesh Cut 是一个基于 C++、DirectX 11 和 DirectXMath 的交互式网格切割演示。用户在窗口中拖动鼠标，由起终点生成三维切割平面。系统在 CPU 上裁剪三角形、恢复截面轮廓、生成两侧封口，最后重建用于绘制的模型资源。

当前支持平面切割、交点属性插值、简单凹轮廓封口、多个独立非嵌套截面以及重复切割。运行时可以拖入 OBJ 更换模型，通过 F1 切换实心／线框，通过 F3 显示／隐藏切割平面；通过双栈快照历史撤销和重做切割。操作提示在 Debug 与 Release 中均显示。

“切开”意味着重新生成三角形表面并分离两侧的位置，不包含碰撞体生成、刚体模拟或切块物理行为。

## 2. 模块与数据流

| 模块 | 职责 |
|---|---|
| `main.cpp` | 接收拖放请求、处理显示模式按键、驱动更新与绘制 |
| `ObjImporter` | 读取 OBJ／MTL，生成顶点、索引、subset 与材质数据 |
| `player.cpp` | 鼠标交互、平面转换、调用几何算法、暂存并提交模型结果 |
| `MeshCutter` | 数学辅助、属性插值、表面裁剪、交线组织、轮廓三角化与封口 |
| `ModelSnapshot.h / .cpp` | 独立模型快照、纹理引用持有、CPU／GPU 状态恢复 |
| `ModelHistory.h / .cpp` | 两个历史栈、切割记录提交、撤销／重做与清空 |
| `renderer.cpp` | DirectX 资源、绘制状态、填充模式与剔除模式组合 |
| `camera.cpp` | 透视相机、矩阵更新与初始状态恢复 |

`MeshCutter.h` 声明类型与接口；非模板方法定义于 `.cpp`；模板定义置于 `.inl`，由头文件末尾包含。几何计算使用 CPU 数据，但当前 `MeshCutter` 也提供 DirectXMath 坐标辅助函数，并非完全不依赖 DirectX 的公共头文件。

切割流程分为：

1. 屏幕拖动生成世界空间平面。
2. 将平面转换到模型局部空间。
3. 按索引取出每个 subset 的展开三角形。
4. 裁剪原表面，同时收集截面交线。
5. 合并节点、恢复闭环、投影到二维。
6. 检查轮廓嵌套，耳切生成封口三角形。
7. 设置两侧封口属性、整体分离两侧。
8. 暂存全部 subset，保存切割前快照，准备新 CPU／GPU 资源，成功后提交模型与历史。

## 3. 屏幕拖动与世界空间切割平面

### 3.1 从屏幕坐标构造射线

窗口坐标 $(s_x,s_y)$ 先转换为标准化设备坐标：

$$
x_{ndc}=\frac{2s_x}{w}-1,\qquad y_{ndc}=1-\frac{2s_y}{h}
$$

其中 $w,h$ 为当前实现使用的 `SCREEN_WIDTH / SCREEN_HEIGHT`。Y 方向翻转是因为窗口坐标向下增大，而投影坐标向上增大。

对于当前常规对称透视投影，垂直视场角为 $\theta_y$、宽高比为 $a$：

$$
P_{11}=\frac{1}{\tan(\theta_y/2)},\qquad P_{00}=\frac{P_{11}}{a}
$$

在观察空间取 $z=1$，得到射线方向：

$$
D_{view}=\left(\frac{x_{ndc}}{P_{00}},\frac{y_{ndc}}{P_{11}},1\right)
$$

`CreateWorldRayDirection()` 使用逆视图矩阵变换方向并归一化。方向不受相机平移影响；射线起点则通过将观察空间原点变换到世界空间取得。

这里的下标从零开始：$P_{00}$ 和 $P_{11}$ 分别是投影矩阵的 X、Y 缩放项。若两者均为 1，则对应垂直视场角 $90^\circ$、宽高比 1 的对称透视模型，并非正交投影。方向用 `w=0` 构造，并通过 `XMVector3TransformNormal()` 变换；相机平移不参与方向变换。

省略除以 $P_{00}/P_{11}$ 并不会变成正交射线。它仍是从同一起点发散的方向，只是相当于使用不匹配的投影参数。当前公式不用于正交或偏心投影，也假定鼠标映射与全窗口视口一致。

### 3.2 两条射线确定平面

拖动起终点对应单位方向 $D_s,D_e$，共享相机起点 $O$：

$$
N=\mathrm{normalize}(D_e\times D_s),\qquad Q=O
$$

平面满足：

$$
(P-Q)\cdot N=0
$$

屏幕拖动短于 2 像素时不执行切割；叉积长度平方小于 $10^{-12}$ 时也不继续归一化。这些是当前实现的数值保护阈值。

### 3.3 拖动范围接受条件

平面在数学上无限延伸，因此每条截面线段的端点还会通过 `IsInsideStroke()` 检查。交点经模型、观察、投影矩阵得到齐次坐标，执行一次透视除法后返回屏幕坐标，再与拖动起终点构成的轴对齐矩形比较，矩形各方向增加 2 像素余量。

它不是严格的点到拖动线段距离检测。当前实现还拒绝 $w\leq10^{-5}$ 的交点。某条交线端点不满足条件时，当前 subset 返回 `Unchanged`；其他 subset 仍可独立得到有效切割结果。

`Slice()` 接受一个回调，用于执行这项交互条件；不需要屏幕范围限制时，可以使用始终接受的重载。

## 4. 世界空间到模型局部空间

绘制与切割使用相同世界矩阵，采用行向量约定：

$$
W=SRT
$$

模型旋转包含当前项目的 Y 轴额外 $\pi$ 朝向修正。平面上的点和法线转换方式不同：

$$
Q_{local}=Q_{world}W^{-1}
$$

$$
N_{local}=\mathrm{normalize}(N_{world}W^T)
$$

一般法线规则是“对当前坐标变换矩阵取逆转置”。此处坐标变换为 $W^{-1}$，因此法线矩阵为：

$$
\left((W^{-1})^{-1}\right)^T=W^T
$$

这样在非均匀缩放下仍能保持法线与对应平面垂直。该过程假定世界矩阵可逆，不将零缩放作为有效操作。

## 5. 输入三角形与有符号距离

`CutMeshes()` 从 `IndexArray` 解引用顶点，按三个索引一组构建 `Slice()` 的输入。输入是展开三角形序列，不假设索引位置与顶点编号相同。

单位法线下，顶点 $P$ 到平面的有符号距离为：

$$
d=(P-Q)\cdot N
$$

$d>0$ 为正侧，$d<0$ 为负侧。当前默认位置容差为 $\epsilon=10^{-4}$；当 $|d|\leq\epsilon$ 时，将判定使用的距离置零。

此操作仅改变分类值，不将顶点位置移动到平面。容差以模型局部单位计，需结合资产尺度理解。整个输入没有同时出现正负侧顶点，或没有交线节点时，返回 `Unchanged`。

## 6. 半空间裁剪与交点属性

### 6.1 两次 Clip 分别生成两侧

`Clip()` 一次只保留一个半空间：

$$
d\times side\geq0
$$

`side=+1` 保留正侧，`side=-1` 保留负侧。平面上的顶点同时属于两侧边界。

沿原三角形边界依次处理 A→B：

| A 在本次保留范围 | B 在本次保留范围 | 当前边追加的顶点 |
|---|---|---|
| 是 | 是 | A |
| 是 | 否 | A、交点 |
| 否 | 是 | 交点 |
| 否 | 否 | 无 |

每条边负责自己的起点，因此普通情况下无需重复追加终点。结果是保持边界顺序的凸多边形，再通过三角扇 $(P_0,P_i,P_{i+1})$ 拆成三角形。

通常的横穿切割中，一个原顶点单独位于一侧，得到一个三角形；另一侧得到四边形并拆成两个三角形。两次 `Clip()` 共同生成这两侧。未被穿过的三角形则原样进入所属侧。

三角扇适用于这里的凸裁剪结果，不负责后续可能为凹形的截面封口。

### 6.2 交点参数与插值

边端点有符号距离为 $d_A,d_B$，交点参数：

$$
t=\frac{d_A}{d_A-d_B}
$$

因为 $d(t)=d_A+t(d_B-d_A)$，令其等于零即可求得该式。随后：

$$
P=A+t(B-A)
$$

同一个 $t$ 用于位置、UV、RGBA 顶点色和法线的线性插值；插值法线再归一化。无需通过交点到端点的长度重新计算参数。未显式处理的额外顶点字段继承端点 A，不应视为自动支持切线或骨骼属性。

### 6.3 三角形有效性

`Triangle()` 保持调用者给出的绕序，仅保存满足下式的面：

$$
\left\|(B-A)\times(C-A)\right\|^2>\epsilon^4
$$

叉积长度为三角形面积的两倍，因此相当于面积大于 $\epsilon^2/2$。该规则过滤退化或过小三角形，但不是完整的网格修复器，也不能单独保证封闭性。裁剪时平面上顶点可能在多边形中重复出现，产生的零面积三角形由此过滤。

## 7. 截面交线与去重

原表面裁剪与封口交线收集使用独立输出：`Clip()` 写两侧表面；每个三角形的 `hits` 收集不同交点。两者当前会重复执行部分求交计算。

平面上的原顶点直接登记；两端距离严格异号的边通过插值登记交点。当前三角形若得到两个交点，就贡献一条截面线段。

| 处理 | 范围 | 作用 |
|---|---|---|
| `AddUniqueIntersection()` | 单个三角形 | 合并位置容差内的交点，正确统计 `hits` |
| `FindOrAddCutNode()` | 整个当前 subset | 让相邻三角形的相同交点使用同一节点编号 |
| 邻居连接查重 | 一对节点 | 避免重复登记同一条无向交线 |

位置相同但编号不同的端点无法直接组成连续轮廓，因此全局节点合并是拓扑恢复的一部分。当前位置去重使用线性查找，保留首次登记的节点属性，不计算平均位置。

`hits` 为 0 或 1 时不产生有长度的交线；为 2 时登记线段；为 3 时，当前实现将其视为共面／不明确情况并拒绝本次切割。容差会影响这些分类。

### 7.1 沿已有边界与共面三角形

两个交点并不等于真正把模型分成了两侧。平面恰好经过一条已有边时，该三角形也可能得到两个交点，而第三个顶点只位于一侧；这条边仍可贡献截面线段。如果整个输入在平面正负两侧都有严格分类的顶点，并且交线能形成支持的闭环，即使没有三角形被从内部穿过，也可能沿已有网格边完成切割。若只是贴着模型外表面经过、没有两侧顶点，则不会提交切割。

如果一个非退化三角形的三个不同顶点都被判定在平面上，当前实现得到三个交点并返回 `OpenOrAmbiguousContour`。这是一项有意保留的限制：即使模型其他区域分布在平面两侧，该共面三角形也会令本次模型更新取消。实现没有进一步决定如何归属、保留或替换共面面片。

在拒绝之前，`Clip()` 可能已经生成临时表面结果；这些结果不会提交。因此，“拒绝共面三角形”不代表 `Clip()` 完全没有输出，而是本次操作的最终结果不被采用。

## 8. 邻接关系与闭环恢复

`nodes[i]` 保存交点，`adjacency[i]` 保存连接到它的其他节点编号。每条线段 AB 双向登记 A→B、B→A。

正常闭合截面要求每个节点恰好有两个邻居。`BuildClosedContours()` 从未访问节点出发，记录当前节点，再选择不是上一节点的另一个邻居，直至回到起点。

- 回到当前起点：完成闭环。
- 提前进入其他已访问节点：失败。
- 邻居数量不为 2，或轮廓少于 3 个节点：失败。
- 外层继续寻找未访问节点：恢复其他独立轮廓。

循环每次登记一个新节点，回到起点或遇到已访问节点就退出，因此在有效编号前提下不会无限遍历。两个邻居只证明连接结构符合闭环要求，不完整检测几何自交。

## 9. 平面二维坐标与嵌套检查

选择不接近平行于单位法线的参考轴 $R$：当前规则在 $|N_x|<0.9$ 时选 X 轴，否则选 Y 轴。构造：

$$
U=\mathrm{normalize}(R\times N),\qquad V=N\times U
$$

其中 $U\times V=N$。将节点投影：

$$
p_u=(P-Q)\cdot U,\qquad p_v=(P-Q)\cdot V
$$

`projected[i]` 与 `nodes[i]` 编号保持一致，`loops` 只存储有序节点编号。

`IsPointInsideContour()` 使用向右水平射线的奇偶规则：跨越边界奇数次为内部，偶数次为外部。`HasNestedContours()` 取每个轮廓的一个节点，检查它是否位于另一轮廓内部。

该代表点判断假定各轮廓简单、互不交叉且不接触，不是全面的轮廓相交检测。检测到嵌套时返回 `UnsupportedHole`，不尝试把孔填成实心面。

## 10. 绕序与耳切三角化

### 10.1 统一逆时针

二维有向面积的两倍：

$$
A_2=\sum_i(x_i y_{i+1}-y_i x_{i+1})
$$

负值时反转轮廓，统一为逆时针。邻接遍历的起步方向不固定，所以这一步在耳切前执行。

### 10.2 选择耳朵

对相邻节点 A、B、C：

$$
Orient(A,B,C)=(B_x-A_x)(C_y-A_y)-(B_y-A_y)(C_x-A_x)
$$

逆时针轮廓中，正值表示凸角。当前仅接受 $Orient>\epsilon^2$ 的候选。

再检查其他轮廓顶点 P 是否同时满足：

$$
Orient(A,B,P)\geq-\epsilon^2
$$
$$
Orient(B,C,P)\geq-\epsilon^2
$$
$$
Orient(C,A,P)\geq-\epsilon^2
$$

满足时，P 位于候选三角形内部或容差边界内，该候选不作为耳朵。否则保存 ABC，并仅从工作轮廓删除 B。剩余轮廓继续处理，最后登记三个节点构成的三角形。

每个轮廓使用副本，节点表和原轮廓不被删除。成功完成时，一个含 n 个节点的简单轮廓生成 n−2 个三角形。某轮找不到耳朵，或最后三角形面积不满足阈值时，返回 `TriangulationFailed`。

`TriangulateContours()` 输出 `TriangleIndices`，只保存三元节点编号；封口顶点生成是后续独立阶段。

## 11. 两侧封口、法线与 UV

`AppendCapTriangles()` 根据节点编号生成两侧封口。`CreateCapVertex()` 复制交点位置与颜色等字段，再覆盖切面法线和 UV。

| 切块 | 封口外法线 | 三角形顺序 |
|---|---|---|
| 负侧 $d\leq0$ | $+N$ | A、B、C |
| 正侧 $d\geq0$ | $-N$ | C、B、A |

绕序控制几何朝向；`Normal` 字段控制保存的光照法线，两者分别设置。原表面边缘与切面边缘可以位于同一位置，但使用不同法线，形成清晰硬边。

平面 UV 为：

$$
(UV_x,UV_y)=(p_u,p_v)\times uvScale
$$

默认 `uvScale=0.1`，不自动将截面归一化到 [0,1]；超出范围后的效果由采样器和材质决定。切面沿用当前 subset 材质，不创建专用切面材质。

最后对每侧的原表面与封口统一偏移：

$$
P_-=P-N\times separation,\qquad P_+=P+N\times separation
$$

默认每侧移动 1.5 个局部单位，因此两侧原本重合的切面间距为 3 个局部单位。完成后返回 `Status::Cut`。偏移发生在 CPU 顶点中，后续切割直接处理这些结果。

## 12. subset 暂存与模型更新

当前算法逐 subset 调用。`PendingSubset` 的 `primaryVertices` 总是存在：切开时保存负侧，未切开时保存原数据；`additionalVertices` 只在切开时保存正侧。它们描述提交角色，而非统一的几何方位。

所有 subset 先在局部 `pending` 中暂存：

- `Cut`：保存两侧。
- `Unchanged`：保存原 subset，避免重建整个模型时丢失它。
- 其他算法失败状态：放弃整次模型更新。
- 所有 subset 都没改变：不重建资源。

通过容量检查后，将最终数组交给更新队列。`TryUpdateModel()` 统计非空数组，创建新的展开顶点、顺序索引和 subset／材质表，再创建独立的新顶点缓冲与索引缓冲。所有准备成功后，才释放旧模型并安装新资源。

新模型顺序索引为 0、1、2……。当前索引与计数字段为 16 位，最多接受 65,535 个展开顶点，不会无限次细分。

### 结果状态

| 状态 | 含义 |
|---|---|
| `Unchanged` | 没有采用本次切割，维持该 subset 的原数据 |
| `Cut` | 两侧表面与封口生成完成 |
| `InvalidInput` | 切割输入或设置不符合当前要求 |
| `OpenOrAmbiguousContour` | 交线开放、分叉、共面或无法按当前规则恢复闭环 |
| `UnsupportedHole` | 检测到不支持的嵌套轮廓 |
| `TriangulationFailed` | 耳切无法完成，或最后三角形未通过面积条件 |

失败结果即使带有部分临时顶点，也不会被当作完整网格提交。

## 13. 资源所有权与失败处理

| 阶段／资源 | 管理方式 |
|---|---|
| 尚未提交的 subset 数组 | `unique_ptr<SimpleArray<VERTEX_3D>>` |
| 已交给更新队列的临时数组 | `QueueCleanup` 离开函数时删除并清空记录 |
| 尚未安装的 CPU 数组 | `unique_ptr<T[]>` |
| 尚未安装的 GPU 缓冲 | 局部 `BufferOwner`，失败退出时 `Release()` |
| 已安装的模型 | `UnloadModel()` 释放纹理引用、缓冲、数组及外层 `MODEL` |

临时材质队列借用原纹理指针，不额外释放纹理。最终每个新 subset 在释放旧模型前为纹理增加一次 `AddRef()`，之后旧 subset 释放原引用，使共享纹理在替换期间保持有效。

成功交接 CPU 数组时使用 `release()`；交接 GPU 缓冲后将临时所有者指针置空。局部清理对象必须实际创建，只有类型声明不会执行析构。

该路径处理已有的算法返回、参数／容量拒绝、内存分配失败和缓冲创建失败，不是对所有导入错误或所有可能异常的完整恢复系统。`SimpleArray` 内部缓冲的释放依赖容器自身既有析构约定。

## 14. 快照与撤销／重做

### 14.1 快照保存什么

`ModelSnapshot` 保存独立的顶点数组、索引数组和 subset／材质数组。顶点中的位置、法线、颜色、UV，以及之前切割生成的封口和分离偏移，都属于保存的模型状态。快照不保存 GPU 缓冲，也不记录相机、模型展示变换、填充模式或切割平面显示开关。

`Capture()` 深拷贝 CPU 数组，但不复制纹理像素。每个保存的 subset 为其纹理调用一次 `AddRef()`；快照析构时，对应调用 `Release()`。快照禁止复制，由 `unique_ptr<ModelSnapshot>` 独占管理。

`Restore()` 根据快照复制新的 CPU 数组，保留保存的索引和 subset 范围，再创建顶点缓冲与索引缓冲。它不需要通过切割暂存队列，也不重新执行几何算法。全部资源准备成功后，先为恢复后的模型取得独立的纹理引用，再通过 `UnloadModel()` 释放旧模型并安装新资源。分配或缓冲创建失败时，当前模型保持原样。

### 14.2 两个栈

`ModelHistory` 使用两个 `std::stack<std::unique_ptr<ModelSnapshot>>`：撤销栈与重做栈。当前模型不直接保存在任一栈顶；栈中保存的是可恢复的其他状态。

| 操作 | 恢复来源 | 当前状态保存到 |
|---|---|---|
| 撤销 | 撤销栈顶 | 重做栈 |
| 重做 | 重做栈顶 | 撤销栈 |

例如 A 经两次成功切割变成 C：当前显示 C，撤销栈从底到顶为 A、B。撤销后显示 B，撤销栈剩 A，重做栈为 C。再次撤销显示 A，重做栈从底到顶为 C、B；重做时先恢复 B，再恢复 C。

一次撤销并不是把同一快照从一个栈搬到另一个栈。恢复源保存 B，而放入另一栈的是刚刚捕获的当前状态 C。

### 14.3 历史与模型一起提交

成功切割的处理顺序为：完成算法和容量检查 → `PrepareCut()` 捕获旧模型并临时压入撤销栈 → `TryUpdateModel()` 尝试替换模型 → `FinishCut()` 确定历史结果。局部 `CutHistoryGuard` 保证离开作用域时执行收尾。

更新成功时保留临时撤销记录并清空重做栈；更新失败时弹出临时记录，原有重做历史保留。未切中、算法拒绝或容量拒绝发生在历史准备之前，不增加记录。如果快照无法保存，则不继续提交切割。

撤销／重做时也先捕获当前状态，并在改变模型前压入目标栈，因为入栈可能分配内存。恢复失败就弹出刚加入的记录，恢复源保持不动；恢复成功才弹出恢复源。空历史返回 `S_FALSE`，实际恢复成功返回 `S_OK`，二者都不属于 HRESULT 失败。

成功导入另一个模型会清空两个栈；导入失败保留历史。撤销后再成功切割会建立新的编辑分支，原重做记录随之销毁。退出时显式清空历史，及时释放快照及其纹理引用。

### 14.4 输入与资源边界

`Ctrl+Z` 撤销；`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做，左右 Ctrl／Shift 均可。输入检测 Z／Y 的按下边沿，按住不会逐帧重复执行；拖动切割线期间忽略历史快捷键。成功恢复后清除旧切割平面预览，但不改变预览显示开关、填充模式或相机。

历史保存在内存中，不写入文件。每份快照都保存完整 CPU 几何，不是差量记录；当前没有历史条数或内存预算上限。长时间编辑的内存占用会随历史增长。纹理以 COM 引用共享，历史不重复保存纹理像素，也不长期保存每一步的 GPU 网格缓冲。

## 15. OBJ 拖放与状态恢复

窗口通过 `DragAcceptFiles()` 和 `WM_DROPFILES` 接收单个 OBJ 路径；消息阶段只保存请求，下一帧更新时执行同步加载。

宽字符路径转换为加载器使用的 Windows ANSI 代码页；不可表示的字符会被拒绝。目录分隔符统一成 `/`，供现有相对资源路径处理使用。这不等于完整 Unicode 导入。内部引用的 MTL／贴图文件名建议避免空格，文件需满足现有解析器的格式要求。

`ReplacePlayerModel()` 先加载临时模型，成功才交换 CPU 数据和两个 GPU 缓冲，随后释放旧资源。失败时保留当前模型和历史。成功替换后清空撤销栈与重做栈。

成功替换后，位置、旋转、缩放、移动惯性、拖动状态、切割平面数据和相机恢复初始状态；重新拖入同一 OBJ 可以恢复未切割几何。R 仅恢复展示状态，不重新读取几何。拖放手势会被取消并等待左键释放，避免意外触发一次切割。

加载是同步的，没有后台线程。新模型不自动居中或按包围盒调整相机距离。

## 16. 显示模式与操作提示

F1 切换 `D3D11_FILL_SOLID / D3D11_FILL_WIREFRAME`。渲染器预创建两种填充方式与三种剔除方式共六种状态；记录当前填充、剔除选择，通过组合绑定状态，避免 `SetCullingMode()` 覆盖线框设置。

F3 控制切割平面显示。显示还要求预览顶点缓冲已成功写入；首次有效拖动前不绘制未初始化平面。预览用两条射线在距离 15 与 300 处的四个点组成四边形，这些距离只决定显示形状，不限制数学切割平面。

预览展示最近尝试生成的平面，即使几何切割未被接受也可能更新。模型重置和成功的撤销／重做会清除旧预览，但保留显示开关。当前填充方式也会影响预览。

`PrintDebugProc()` 登记每帧操作提示，`DrawDebugProc()` 调用 `DebugTextOut()` 绘制。F1／F3 状态和撤销／重做组合键在 Debug 与 Release 中均显示。`DEBUG_DISP_TEXTOUT` 控制文字绘制支持；启用时使用 BGRA 后缓冲与 GDI 兼容交换链。相机旋回、升降、距离控制及 R 重置在 Debug 与 Release 中均启用；D3D 调试层仍仅在 Debug 中启用。

| 操作 | 功能 |
|---|---|
| 鼠标左键拖动并释放 | 尝试切割 |
| 拖入单个 OBJ | 替换并重置；成功后清空历史 |
| Ctrl + Z | 撤销 |
| Ctrl + Y / Ctrl + Shift + Z | 重做 |
| F1 | 实心／线框 |
| F3 | 切割平面显示／隐藏 |
| 方向键 | 相对相机朝向移动模型 |
| A / D | 相机水平旋回 |
| W / N | 相机升高／降低 |
| U / M | 相机靠近／远离 |
| R | 模型变换与相机重置，不恢复几何 |
| Esc | 退出 |

相机旋回使用 A／D、上移使用 W，不再占用 Z／Y，因此相机无需增加 Ctrl 冲突判定。

## 17. 运行环境与当前限制

在 Windows 的 Visual Studio 项目中构建，保持源码使用的 DirectX 11、DirectXMath、输入及 D3DX11 依赖可用。使用当前项目的 C++17 配置，确认 Shader／资产相对路径与工作目录匹配。OBJ 建议预先三角化，提供法线、UV、明确材质分组与有效 MTL／贴图引用。

当前边界：

- 每个参与封口的 subset 需要提供可形成闭环的表面。多材质将同一闭合物体拆成开放面片时，可能因开放轮廓而拒绝切割。
- 支持简单凹轮廓，不支持含孔轮廓、自交处理或通用网格修复。
- 三个不同顶点均被判定在平面上的共面三角形会导致整次更新被拒绝，即使其他区域位于平面两侧。过小几何或容差合并导致的异常连接也可能被拒绝；拒绝不等于几何修复。
- 历史保存完整 CPU 几何，当前没有历史条数／内存预算限制，也不提供历史持久化。
- 线框显示三角化边，不是仅显示物体轮廓线的描边效果。
- 不支持曲线刀面、任意布尔实体、碰撞和刚体动力学。
- 节点合并为线性查找；逐次搜索候选耳朵并扫描其他顶点的实现，最坏可达立方复杂度。不宣称完成大规模网格性能优化。
- 16 位数据容量、资产尺度和数值容差限制重复切割的深度与稳定性。

建议演示顺序：立方体平切与斜切 → 连续撤销／重做 → 撤销后重新切割验证分支 → L 棱柱凹截面 → F1 检查三角化 → F3 检查平面 → 重新拖入模型恢复几何并清空历史。
